# THE DEFERRED CORRECTION IN REFERENCE COORDINATES: the Grace A/B, both passes.
#
# The change under test (one working tree, uncommitted at the time of measurement):
#   * the correction's node-to-centroid vectors come from the element Jacobian's edge columns,
#     x_s - x_a = J (xi_s - xi_a), and the staged gradient pack is rewritten in place into the
#     twenty-four node-surface increments once per element (cvfem_hex8_defcor_ref_increments);
#     no node coordinates are staged and no centroids are built;
#   * each limiter's value and derivative come from one fused call sharing one reciprocal;
#   * Venkatakrishnan's eps^2 is formed per direction group outside the lane loop.
#
# Reference: the tree at 9b62d097f, the commit the paper's higher-order table was measured on.
# Both binaries gcc 13.3 under prgenv-gnu/24.11:v2 against installations/sfem-omp, run by
# jobs/ab_refactor.sbatch -> scripts/perf_regression.sh --against: one allocation, order
# alternating every rep, medians of 9, n=128 (8,586,756 dofs), 72 threads.
#
# PASS 1, job 5003520 (nid006545): the increments pre-pass as one lane per call with the node and
# component loops inside it, under the dispatcher's `#pragma omp simd` lane loop. gcc did not
# vectorise it -- -fopt-info-vec-all: "couldn't vectorize loop" on the node loop and "not
# profitable" for SLP on the body -- so the pre-pass ran scalar, twice per lane group on the
# Jacobian. The residual arms gained in spite of it; the Jacobian arms lost, and the gate's
# confirmation pass reproduced the loss.

# WHAT THE TWO PASSES SAY. The residual's gain is the removed work: the centroids, the coordinate
# staging and the per-surface dot products were a third of the correction's arithmetic and it is
# now 16-26% faster at the paper's own configuration. The Jacobian action is unchanged within
# the band, which is what removing the same work and adding a second in-place pass over the
# direction's pack comes to on that kernel; what it does NOT do is regress, and pass 1 is kept
# here because the only difference between -8% and 0% was the nesting of one loop that the
# laptop's compiler vectorised either way. Every first-order row is unchanged, as it must be --
# none of this code is reached without --conv-ho.
