\begin{abstract}
Low-order matrix-free operators accumulate contributions at shared mesh nodes,
usually through atomic updates or colouring. We present a packed mesh format that
resolves these write conflicts through ownership. Each node belongs to one pack
of elements. A pack accumulates into a private buffer, writes its owned rows, and
stages the remaining contributions for a sorted gather. The application uses no
atomic additions or barriers between colours; the local phase completes before
ghost reduction. Stored index arrays fix the summation order when one thread owns
each pack, while the solution vector retains one entry per global unknown.

We evaluate residuals and Jacobian actions of a colocated CVFEM Navier--Stokes
discretisation on an NVIDIA Grace CPU, using affine and procedural irregular
hexahedral meshes. Matched affine FP64 residual measurements with Rhie--Chow coupling give packed speedups
of $\matchedFoSpeedup\times$ for first-order convection and
$\matchedDarwishSpeedup\times$ for the Darwish correction. Counted memory traffic
is comparable between layouts. Separate controlled probes find substantial
accumulation savings at both one and 72 threads, including memory and
synchronization effects. These probes do not isolate atomic-instruction latency.
The matrix-free lagged action also outperforms the equivalent sparse product in
the tested case. Exact actions retain additional reconstruction sensitivities
and are reported separately from that matrix baseline. The results establish an
operator-application benefit; solver runtime gains are not measured.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Matrix-free operators gather nodal values, evaluate element kernels and scatter
contributions back to shared mesh nodes. Concurrent writes are commonly resolved
with atomics or element colouring. Atomics allow flexible traversal but leave
floating-point summation order dependent on thread arrival; colouring fixes an
order and removes atomics, while introducing barriers between colours.
Assembly moves the accumulation to setup, replacing element application with a
sparse product whose storage grows with the stencil.

We instead resolve the conflict through ownership. Elements form packs, each
node belongs to exactly one pack, and owned node ranges partition the numbering.
Pack-private accumulation uses ordinary additions; owned rows are assigned and
ghost contributions are staged for a sorted gather. Stored indices fix the
summation order with one thread per pack. For fixed inputs, packing and compiled
arithmetic, this gives bitwise reproducibility across thread counts without
redundant global solution entries.

\begin{samepage}
\noindent\textbf{Contributions.}
\begin{itemize}
  \item A mesh format whose ownership structure makes the matrix-free scatter
        \emph{atomics-free by construction} rather than by synchronisation, on any number of
        threads (\S\ref{sec:format}).
  \item An argument from three properties of the layout, with measurement, that operator
        application with one thread per pack and fixed inputs, packing and arithmetic
        is \emph{bitwise reproducible} across thread counts
        (\S\ref{sec:apply}, \S\ref{sec:res:determinism}).
  \item An evaluation on a solver's operators against an atomic sweep and against lagged
        sparse matrix--vector products, reported along a \emph{term-completeness ladder} and
        across convective schemes, identifying which solver terms each measured operator includes
        (\S\ref{sec:res:throughput}).
  \item A pack-size study identifying \emph{packs per thread} as the useful tuning axis
        over the tested sizes and kernels, with a default derived from the core count (\S\ref{sec:res:packsize}).
\end{itemize}
\end{samepage}

\section{Related work}
\label{sec:related}

\paragraph{Matrix-free operator application.} Evaluating an operator from its element
contributions rather than from an assembled matrix is long established for high-order
discretisations, where the assembled stencil grows quickly with the polynomial degree and sum
factorisation makes the element kernel cheap~\cite{Orszag1980,DevilleFischerMund2002,Brown2010}.
Modern libraries and form compilers build on that lineage~\cite{KronbichlerKormann2012,KronbichlerKormann2019,MFEM2021,libCEED2021,Kolev2021,KirbyLogg2006,Firedrake2016}.
At degree one, sum factorisation improves an already short element kernel; indexed
input traffic and output accumulation remain significant. This paper targets
those surrounding operations rather than the kernel's arithmetic.

\paragraph{Scatter, locality and reproducibility.} Cecka et
al.~\cite{CeckaLewDarve2011} compare GPU atomic and colouring strategies.
Colouring partitions work into conflict-free phases; packing assigns exclusive
ownership and gathers staged contributions. Both can fix summation order.
Space-filling reordering is established for locality and partitioning~\cite{Bader2013,Zumbusch2001};
here it keeps contiguous packs' node sets small. Graph partitioning can instead
minimise cuts directly~\cite{PothenSimonLiou1990,KarypisKumar1998,PellegriniRoman1996},
then order elements by part. Reproducible arithmetic makes sums independent of
order~\cite{DemmelNguyen2013}; our complementary approach stores a fixed order.

\paragraph{Prior art.} Blocking elements with locally numbered nodes is not novel, nor is
space-filling reordering; what they achieved is the question. Reguly and Giles~\cite{RegulyGiles2015} use blocking and local numbering
for locality, with colouring or atomics still resolving writes. Settgast et al.~\cite{Settgast2023} make the low-order matrix-free case on
GPUs with the same standard scatter. Wichrowski~\cite{Wichrowski2026} instead keeps
solver vectors in redundant cell-wise storage and enforces continuity inside the
preconditioner. Its direct stiffness summation uses axis passes within structured
blocks and separate face, line and vertex kernels for unstructured interfaces;
a general unstructured path is also evaluated. The reported \SI{14.1}{}~GDoF/s
at $\mathbb{Q}_1$ is a cell-local Cartesian Laplace rate on an A100, excluding
direct stiffness summation and per-quadrature geometry reads. It is therefore not
a complete-operator comparison with the CVFEM measurements here. Cell-wise storage
approaches $8\times$ redundancy at $\mathbb{Q}_1$; optional $2^3$-cell clusters
reduce that ratio to $27/8\simeq3.38$, but are not benchmarked in that work.

The packed format retains one global entry per unknown and uses exclusive pack
ownership, temporary accumulation buffers and a gather built by sorting. It does
not require structured interiors for the gather. These are complementary storage
choices: cell-wise vector redundancy falls with polynomial degree, while the
present measurements target low-order CPU operators. This distinction does not
imply that cell-wise storage is ineffective at low order. We also compare against
element colouring, which changes traversal and accumulation together
(\S\ref{sec:res:scaling}).

\section{The packed format}
\label{sec:format}

\subsection{Packs and reordering}

A \emph{pack} is a contiguous range of element indices together with the nodes those elements
touch: element $e$ belongs to pack $p = \lfloor e / n_{\mathrm{epp}} \rfloor$
(Figure~\ref{fig:decomposition}).

The mesh must be spatially reordered first, by a space-filling curve here, or a pack's elements
are scattered and the node set they touch is large; \S\ref{sec:res:ordering} measures the cost
of skipping it. Packing then renumbers the nodes in place, so everything indexed by node is
built after it --- the coordinates, and the sparsity pattern where a matrix is assembled at all.

\subsection{Node identity}
\label{sec:format:zones}

Each node has exactly one owning pack (Figure~\ref{fig:decomposition}), and pack $p$ owns a
contiguous, monotonically increasing
range of global indices. The owned ranges therefore \emph{partition} $[0, n_{\mathrm{nodes}})$.
Writing $n_c(p)$ for the size of that range, a pack-local index $\ell$ resolves to a global one
as
\[
  g(p,\ell) =
  \begin{cases}
    \texttt{owned\_nodes\_ptr}[p] + \ell, & \ell < n_c(p),\\[2pt]
    \texttt{ghost\_idx}\big[\texttt{ghost\_ptr}[p] + \ell - n_c(p)\big], & \ell \ge n_c(p).
  \end{cases}
\]
Algorithm~\ref{alg:build} advances one numbering cursor by $n_c$ per pack
(line~\ref{ln:advance}); ownership is recoverable by binary search.

The pack-local index is a \emph{16-bit unsigned integer}. That is the single most consequential
choice in the format and it cuts both ways: it halves the index traffic of the element sweep
against the \SI{32}{\bit} global index a flat sweep must use (\S\ref{sec:cost}), and it caps a
pack at $2^{16}$ distinct nodes. That cap is a correctness bound on the pack size;
\S\ref{sec:res:packsize} shows what should set it instead.

Within the owned range the indices are ordered \emph{non-shared first, then shared}, which is
what the two cursors of Algorithm~\ref{alg:build} produce (line~\ref{ln:cursors}). With $n_s(p)$
the number of a pack's owned nodes that some other pack also touches, the local index space
splits into three zones:
\begin{center}
\begin{tabular}{ll}
\toprule
range of $\ell$ & property \\
\midrule
$0 \le \ell < n_c - n_s$ & owned, touched by no other pack \\
$n_c - n_s \le \ell < n_c$ & owned, also touched elsewhere \\
$n_c \le \ell < n_{\mathrm{pack}}$ & ghost: touched, not owned \\
\bottomrule
\end{tabular}
\end{center}

The split earns nothing on a CPU, where one thread owns a pack and the whole flush of the owned
range is already contention-free. It is there for the case of several threads to a pack, where
the first zone can be written without synchronisation and only the shared tail cannot.

\subsection{Ghost lists and the reduction graph}
\label{sec:format:ghost}

A pack's elements contribute to nodes it does not own, and those contributions cannot go to the
global array: another pack owns the row. They are \emph{staged} instead, one slot per pack and
ghost node, and summed afterwards. Two things make this cheap. The slot is written by its pack
alone, so staging is a store and not a read-modify-write; and it is the minority path. On the
$n=\campN$ cube at the \fpPack-element pack size used throughout, those slots number
\fpGhostPct\% of the mesh's nodes, and the summation that empties them averages
\fpGhostPerRow{} terms per destination. Every owned row has gone straight to the global array
already.

The sum is taken over a \emph{reduction graph}, built by sorting (destination, slot) pairs and
grouping them (Algorithm~\ref{alg:build}, line~\ref{ln:sort}). Sorted pairs group into one row
per destination, so one thread owns each destination and no atomic is required, and within a
row the slots are visited in a stored order, so the sum is the same sequence of floating-point
additions on every run.

\subsection{Construction}
\label{sec:format:build}

Everything above is produced by five sequential passes over the connectivity,
Algorithm~\ref{alg:build}. The mesh is already spatially reordered when they start, and the only
parameter is $n_{\mathrm{epp}}$.

\begin{algorithm}
\caption{Building the packed format from a reordered mesh}
\label{alg:build}
\begin{algorithmic}[1]
\Statex \textbf{Pass 1 --- ownership}
\ForAll{packs $p$ in increasing order}
  \ForAll{nodes $v$ of the elements of $p$}
    \If{$v$ is unclaimed} \State $\mathrm{owner}[v] \gets p$ \label{ln:own}
         \Comment{first touch wins}
    \EndIf
  \EndFor
\EndFor
\Statex \textbf{Pass 2 --- sharing}
\ForAll{packs $p$, nodes $v$ of the elements of $p$}
  \If{$\mathrm{owner}[v] \neq p$} \State mark $v$ shared
  \EndIf
\EndFor
\Statex \textbf{Pass 3 --- renumbering} \Comment{$\mathrm{next} \gets 0$}
\ForAll{packs $p$ in increasing order}
  \State $n_c \gets |\{v : \mathrm{owner}[v] = p\}|$, \; $n_s \gets$ how many of those are shared
  \State $a \gets \mathrm{next}$, \; $b \gets \mathrm{next} + n_c - n_s$ \label{ln:cursors}
  \ForAll{nodes $v$ of the elements of $p$, first appearance only}
    \If{$\mathrm{owner}[v] = p$}
      \State $\mathrm{map}[v] \gets b{+}{+}$ \textbf{if} $v$ shared \textbf{else} $a{+}{+}$
    \Else{} \State charge one ghost slot to $p$
    \EndIf
  \EndFor
  \State $\mathrm{next} \gets \mathrm{next} + n_c$ \label{ln:advance}
\EndFor
\Statex \textbf{Pass 4 --- pack-local connectivity}
\ForAll{packs $p$, nodes $v$ in a node-major sweep of $p$'s elements}
  \If{$\mathrm{owner}[v] = p$}
    \State local id $\gets \mathrm{map}[v] - \texttt{owned\_nodes\_ptr}[p]$
  \Else
    \State append $\mathrm{map}[v]$ to $p$'s ghost list on first appearance; \label{ln:ghost}
    \Statex \hskip\algorithmicindent\hskip\algorithmicindent
            local id $\gets n_c(p) + (\text{its position there})$
  \EndIf
\EndFor
\Statex \textbf{Pass 5 --- reduction graph}
\State sort the pairs $(\mathrm{map}[v], j)$ over all ghost entries $j$ \label{ln:sort}
\State group by destination into \textsc{csr} rows
\end{algorithmic}
\end{algorithm}

Ownership is first touch in element order (line~\ref{ln:own}). Nodes outside the
packable prefix keep their numbers and occur only as ghosts. Renumbering issues
ids on first appearance, placing nearby sweep entries nearby in memory. The
construction is linear in connectivity apart from the final sort, and is
amortised over applications on the same mesh.

\section{Operator application}
\label{sec:apply}

\subsection{The two-pass algorithm}

The apply runs in the two phases of Figure~\ref{fig:reduction}: a parallel pass over packs,
then a parallel pass over the rows of the reduction graph.

\begin{algorithm}
\caption{Packed operator application}
\label{alg:apply}
\begin{algorithmic}[1]
\Statex \textbf{Phase 1 --- local accumulation}
\ForAll{packs $p$ \textbf{in parallel}}
  \State $A \gets 0$ \Comment{pack-private accumulator, $n_{\mathrm{pack}}(p)$ rows}
  \State gather the input fields into pack-local order
  \ForAll{elements $e$ of $p$, in increasing index}
    \State evaluate the element kernel
    \State $A[\,\text{local node}\,] \mathrel{+}= \text{contribution}$
           \Comment{plain addition, no atomic}
  \EndFor
  \State \textbf{write} $A[0 \ldots n_c)$ to the global array \Comment{assignment, not
         accumulation}
  \State \textbf{store} $A[n_c \ldots n_{\mathrm{pack}})$ into the staging buffer
\EndFor
\Statex \textbf{Phase 2 --- gather}
\ForAll{reduction rows $r$ \textbf{in parallel}}
  \State $\text{global}[\texttt{dest}[r]] \mathrel{+}= \sum_{j \in \text{row } r}
         \text{staged}[j]$
\EndFor
\end{algorithmic}
\end{algorithm}

Both writes out of Phase~1 are assignments, and the ownership partition is why. The owned rows
are \emph{assigned} because no other pack owns them, so the global array never has to be zeroed
and a full pass over the output disappears; the staged values are \emph{stored} because a given
pack and ghost own that slot between them.

The input is read differently too. A flat element sweep reads a node once per incident element,
the packed sweep once per pack node --- on a hexahedral mesh about an eighth as many reads, and
contiguous for the owned majority.

\subsection{Reproducibility}
\label{sec:apply:determinism}

Floating-point addition is not associative, so a reproducible result requires a fixed summation
order, and any fixed order will do. Three properties fix it here, one per path a contribution
can take:

\begin{enumerate}
  \item \emph{Within a pack}, one thread walks the pack's elements in increasing index order,
        and, at fixed pack size, membership is a function of the element index. The order in which a node
        receives its contributions from inside the pack is therefore the same on every run and
        at every thread count.
  \item \emph{Across packs, for owned nodes}, there is no summation to order at all: the owned
        ranges partition the node numbering, so exactly one pack contributes.
  \item \emph{Across packs, for shared nodes}, the reduction graph fixes the order, because
        each destination is one row and the row's terms are visited in a stored sequence.
\end{enumerate}

\noindent
Every path is atomic-free, and by the ownership partition rather than by a choice of
synchronisation primitive.

\paragraph{Scope of the claim.} Input bits, mesh ordering, pack size, reduction graph
and compiled arithmetic must stay fixed. The thread-dependent default pack size
must therefore be pinned in cross-thread comparisons; the reported sweep does so.
Changing the packing can change the summation order. Parallel input generation
can also change last bits independently of the operator. Splitting a pack across
threads would require a fixed in-pack reduction as well.

\subsection{Alternatives}
\label{sec:apply:alternatives}



\paragraph{Atomic.} A flat sweep uses global indices and atomic nodal additions,
with an initial output-zeroing pass. Thread arrival determines the summation
order. Good scaling does not establish negligible update cost; the diagnostic
in Table~\ref{tab:scatter} measures accumulation separately.

\paragraph{Pack colouring.} Conflict-free sets of packs write directly to the
global output. Input staging and local indexing match packed execution, while
output accumulation and barriers between colours differ. This pair therefore
compares accumulation and scheduling together.

\paragraph{Element colouring.} The conventional baseline groups elements into
conflict-free colours. It shares the atomic sweep's lane blocking, geometry
gather and kernel, but replaces atomics with plain additions and introduces
colour-ordered traversal and barriers. Nodal reconstruction uses the same
colouring. Greedy colouring of the spatially ordered mesh retains substantial
locality. Both colourings fix a summation order when constructed deterministically;
the measured reproducibility and performance are reported separately below.
The pack colouring uses \campNColors{} colours, with
\campColorPacksLo{}--\campColorPacksHi{} packs each. Its global additions read
destinations before updating them; packed owned rows have a single writer.
Historical traffic estimates give \colBytesPctResRc\% more transported bytes
for its residual and \colBytesPctJac\% for its bare action, but do not isolate
these reads or establish traffic at every thread count.

\section{Cost model}
\label{sec:cost}

\subsection{Indexing, inputs and outputs}

A flat hexahedral sweep reads eight 32-bit global indices per element
(\SI{32}{\byte}); packed connectivity uses 16-bit local indices
(\SI{16}{\byte}), with no decode step. Input fields are gathered once per pack
node, instead of once per element--node incidence, and owned inputs are
contiguous. Ownership permits assignment of owned outputs and removes the global
zeroing pass. These structural counts do not predict transported traffic or runtime.

\paragraph{Mesh footprint.} At \fpPack{} elements per pack, connectivity falls
from \fpStd{} to \fpConn{}~B/dof, but ownership and ghost metadata make the
implemented total \fpImpl{}~B/dof (\fpImplPct\% of standard).
The apply does not read the \fpNodeMap{}~B/dof numbering permutation;
excluding it gives \fpWorkingPct\%. Narrowing the reduction offsets from
64 to 32 bits would save \fpReduceSaving{}~B/dof, reaching \fpFloorPct\%,
or \fpFloorBigPct\% at pack size \fpPackBig{}. Those changes are not implemented.
Coordinates are identical and excluded; including them gives \fpImplPtsPct\%.
The matrix's $4\times4$ blocks give the larger allocation in
Table~\ref{tab:footprint}; storage alone does not identify a runtime bottleneck.

\paragraph{Operator equivalence.}
The assembled baseline omits the Rhie--Chow pressure-gradient reconstruction
sensitivity. Retaining it would couple pressures beyond the implemented one-ring
sparsity. Exact assembly with expanded sparsity is possible, but is not implemented
or measured here. The baseline therefore represents $\Jlag$, while $\Jex$ retains
the reconstruction sensitivity (\S\ref{sec:setup}). Table~\ref{tab:jacfair} reports
both actions; only the comparison with $\Jlag$ measures equivalent operators.

\paragraph{Discretisation and geometry.} Colocated CVFEM integrates
incompressible Navier--Stokes fluxes over hexahedral sub-control-surfaces,
with three velocities and pressure at each node. The cube campaigns use affine
geometry, caching one Jacobian, adjugate and determinant per element.
The irregular-mesh experiment (\S\ref{sec:res:unstructured}) instead evaluates
trilinear geometry at each sub-control-surface.

First-order upwinding uses a hard donor switch, with no blending band.
Deferred correction~\cite{KhoslaRubin1974,XuePhanThienTanner2002} reconstructs
$u_{\mathrm{face}}=u_{\mathrm{donor}}+\nabla u_{\mathrm{donor}}\cdot
(x_{\mathrm{scs}}-x_{\mathrm{donor}})$ and treats its difference from first
order explicitly. The implicit operator therefore stays first order; this does
not establish diagonal dominance of the coupled system. ``Higher-order'' names
this reconstruction family, not a demonstrated common convergence order.
We test unlimited reconstruction and three limiters (\S\ref{sec:res:convho}).
A separate local manufactured-solution check shows decreasing velocity errors on
three affine grids for all five schemes; its runs meet the nonlinear target but
fail a separate absolute-accuracy gate, so they do not establish a common
asymptotic order.
Nodal gradients sum incident element gradients in a separate completed pass;
pressure reconstruction also supplies Rhie--Chow coupling.

``Exact'' actions retain every reconstruction and flux sensitivity on
differentiable branches. At limiter ties and zero mass flux they use implemented
tie conventions, where a classical Jacobian need not exist. For
$m^+u_L+m^-u_R$, $m^\pm=(m\pm|m|)/2$, the derivatives at $m=0$ differ if
$u_L\ne u_R$. Roundoff can therefore select different branches across layouts
even when their residuals agree.

\paragraph{Operators.} The following names distinguish the retained sensitivities.

$\Gop p(u)$ and $\Gop u(u)$ are the nodal reconstructions of the pressure gradient (3
components) and the velocity gradient (9) at the state $u$, and $\Gop p(v)$, $\Gop u(v)$ the
same reconstructions of a Krylov direction $v$. Each is one element sweep and one ghost
reduction.

$\Fres(u)$ is the residual with first-order upwinding and $\Fho(u)$ the residual with the
deferred correction. Both carry the Rhie--Chow coupling and so read $\Gop p(u)$; $\Fho$ reads
$\Gop u(u)$ as well.

Three Jacobian actions are measured. $\Jex(u)\,v$ is
the exact Jacobian of $\Fres$: it differentiates the coupling through the reconstruction and so
rebuilds $\Gop p(v)$ on every application. $\Jhoex(u)\,v$ is the exact Jacobian of $\Fho$, adding
the differentiated correction and the derivative of the limiter, and rebuilding $\Gop u(v)$ with
it --- in the same sweep as $\Gop p(v)$, since the two read different fields of one array at one
stride. $\Jlag(u)\,v$ omits the convective correction and holds $\Gop p(u)$ fixed.
It drops the pressure-gradient reconstruction sensitivity, while retaining local
pressure and velocity-dependent coefficient derivatives. It reconstructs no
direction gradients.

With the correction explicit, $\Jlag$ is the same for every scheme and
approximates $\Fho$. Action checks do not establish nonlinear convergence.
Keeping only mass-flux sensitivity times the fixed correction increment, while
omitting the increment's direction sensitivity, is an intermediate form not
measured here.

With the higher-order correction treated as an explicit source, $\Jex$ is also the
correction-lagged, RC-exact action. It is an approximate derivative of $\Fho$, and an exact
derivative of the surrogate residual with that source held fixed.

Caching a reconstruction at the current state is distinct from dropping its sensitivity.
For $F(u)=\mathcal{R}(u,g(u))$, differentiation gives
$F'(u)v=\mathcal{R}_u v+\mathcal{R}_g g'(u)v$ wherever the derivatives exist.
During a Krylov solve, $u$ is fixed: $g(u)$ can be reused while $g'(u)v$ is evaluated for
each direction. Both terms are retained in the exact action. The state cache must be
refreshed when the state or geometry changes.

The implemented assembled matrix holds $\Jlag$, for the sparsity reason of
\S\ref{sec:cost}. Algorithm~\ref{alg:jacaction} is where the forms part, and the driver
records which one ran.

\begin{algorithm}
\caption{Jacobian action: $\Jex$, $\Jhoex$ and $\Jlag$}
\label{alg:jacaction}
\begin{algorithmic}[1]
\Require state $u$, direction $v$, cached $\Gop p(u)$ and, for correction, $\Gop u(u)$
\If{exact}
  \State $q\gets\Gop p(v)$; for $\Jhoex$, also $g_v\gets\Gop u(v)$ in the same sweep
\Else
  \State $q,g_v\gets\varnothing$ \Comment{$\Jlag$: correction explicit}
\EndIf
\State apply Algorithm~\ref{alg:apply}: linearise first-order convection, viscosity
       and RC; retain RC reconstruction sensitivity through $q$ when present
\If{$g_v\ne\varnothing$}
  \State add mass-flux sensitivity times the limited state increment, and
         the increment's derivative through $g_v$, including the limiter
\EndIf
\State add boundary and transient sweeps when enabled
\end{algorithmic}
\end{algorithm}

\subsection{Reproducibility}
\label{sec:res:determinism}

Measured at $n=\detN$ over $\detRepeats$ repeats at 72 threads and over one run at each of
$\detThreads$ threads, the atomic sweep agrees with itself in none of the runs: the repeats give
$\detAtomicresRep$ distinct results and the thread counts $\detAtomicresThr$, on the residual and
on the Jacobian action alike. The packed layout gives a single answer in both sweeps, at every
thread count and for both operators.

Both colourings are reproducible here as well, across repeats and across thread counts, as is the
packed layout; all three avoid atomics and so fix a summation order, and they differ in
throughput (\S\ref{sec:res:throughput}). The element-coloured layout fixes its order without a
pack at all: each node takes one contribution per colour, and the colouring depends on neither
the thread count nor a pack size. Two caveats attach to
the colouring result: its reproducibility depends on the colouring being constructed
deterministically, which is a property of the construction rather than the layout, and agreement
over seven runs is evidence rather than proof.

Reproducibility is measured with a fingerprint folding every output value's bit pattern. A
checksum is a running sum over millions of values, so a last-bit difference on a few nodes falls
below the total's unit in the last place: on this operator a checksum reported two runs identical
where a per-node comparison showed hundreds of differing doubles. Fingerprints are compared only
within a layout, since packing renumbers the mesh; operator equivalence across layouts is
established separately, by matching nodes on coordinates.

\subsection{Pack size and the index-type ceiling}
\label{sec:res:packsize}

\begin{figure}[t]
  \centering
  \input{figures/packsize}
  \caption{Throughput of $\Jex$ with the boundary closure against packs per thread, at two
    problem sizes. Solid: first-order upwinding. Dashed: $\Jhoex$ with the Darwish--Moukalled
    limiter. The pack size is the
    knob; packs per thread is the axis on which the collapse is explained.}
  \label{fig:packsize}
\end{figure}

The pack size is the one parameter of the format, and what selects its default is not what
should. A pack may address no more distinct nodes than its index type admits, and the packer
sizes packs against that ceiling using the pessimistic bound (elements $\times$ nodes per
element), which credits no sharing at all. For hexahedra that yields roughly
$\packLargeCeil{}$ elements per pack. But a pack is one unit of parallel work, so the number of
packs \emph{is} the available parallelism, and an index-width ceiling knows nothing about how
many cores the machine has.

At $n=\packLargeN{}$ the ceiling-derived pack leaves $\packLargeCeilPacks{}$ packs for 72 threads
and gives up $\packLargeCeilLoss\times$ against the best size (Figure~\ref{fig:packsize}). At
$n=\packSmallN{}$ it leaves $\packSmallCeilPacks{}$ packs, \packSmallCeilPpt{} per thread, and
throughput falls by $\packSmallCeilLoss\times$. Plotted against packs per thread the two curves
fail together at the same place on this axis while failing at different pack sizes,
consistent with a parallel-granularity limit; these timings do not isolate
cache effects. Arithmetic does
not move the knee either: at \pkszHoWorkFactor$\times$ the work per degree of freedom the limited
higher-order arm falls at the same place, retaining \pkszKneeHo{} of its pre-knee rate against
\pkszKneeFo{} for first order.

The default targets \packsPerThread{} packs per thread, rounded to a power of two
and capped by the index-width bound. It reproduces the measured optimum at the
sizes swept. The pack-size study varies this parameter; thread scaling pins the
72-thread choice. Matched and accumulation studies explicitly use pack size 1024,
including the one-thread accumulation cases.

\subsection{Spatial ordering}
\label{sec:res:ordering}

A pack is a contiguous range of element indices, so the element order decides which nodes it
touches. Replacing the space-filling pass with a lexicographic order at fixed pack size grows the
mean node set per pack from $\ordSfcMean{}$ to $\ordLexMean{}$, and costs
$\ordSfcRes{}\to\ordLexRes{}$~MDOF/s on the residual and $\ordSfcJac{}\to\ordLexJac{}$ on
$\Jex$, both carrying the boundary closure at $n=128$. The ordering is
a precondition of the format, as \S\ref{sec:format} states, rather than an optimisation applied
to it.

\subsection{$\Jhoex$, the exact higher-order Jacobian action}
\label{sec:res:hoexact}

With the correction left an explicit source, $\Jex$ approximates the derivative of $\Fho$
(\S\ref{sec:setup}). $\Jhoex$ also reconstructs $\Gop u(v)$ and differentiates the limiter.
The measurements in this section use the rebuild mode: their fused sweep includes both
state and direction gradients, eight scalar input fields for $\Jhoex$ against two for
$\Jex$. Thus the measured cost includes redundant state reconstruction as well as the
additional sensitivities. In this mode, the unlimited arm reaches
\hoxExactPackedUnlim{}~MDOF/s against Venkatakrishnan's \hoxExactPacked{}, a factor of
$\hoxLimiterCost$.

$\Jhoex$ costs $\hoxCostPacked\times$ $\Jex$, \hoxCorrectionLaggedPacked{} to
\hoxExactPacked{}~MDOF/s, against $\hoxCostAtomic\times$ on the standard layout.
The added work includes reconstruction and differentiated fluxes; these total
times do not assign a cost to each component. The packed speedup is
$\hoxLayoutCorrectionLagged\times$ on $\Jex$ and $\hoxLayoutExact\times$ on $\Jhoex$. The added pass is
itself packed, gathering pack-locally and closing through the same ghost graph the operator
sweeps use.

\paragraph{Action traffic.} The historical Darwish action has estimated traffic
of \hoJacBytesPacked{} bytes per degree of freedom packed and \hoJacBytesAtomic{}
atomic. Its first-order action with Rhie--Chow has \foJacBytesPacked{} and
\foJacBytesAtomic{}, respectively. These captures predate the benchmark's
state-gradient cache correction. The element-work model omits reconstruction work,
so these points do not establish the full action's arithmetic intensity or the effect
of the cache correction.

\paragraph{The reconstruction.} Standalone pressure and velocity gradients
reach \ngPgradPacked{} versus \ngPgradAtomic{}~MDOF/s and
\ngUgradPacked{} versus \ngUgradAtomic{}, respectively, packed versus atomic.
These one- and three-field sweeps differ from the fused eight-field
reconstruction in the recorded $\Jhoex$ runs, so do not establish its action
share. Historical phase fractions counted reconstruction warmup but excluded it
from total time. Both counters now reset before measurement; corrected fractions
require new runs.

The historical unlimited, RC-off check perturbs velocity and rebuilds $\Gop u$:
finite differences agree with the higher-order action to \hoxFdUnlim{}, while
omitting the correction gives \num{6e-2} error. This is not the RC-enabled
$\Jlag$ or a check of every limiter branch. New regressions require relative
infinity error below \num{1e-6} at two step sizes, first for RC-off velocity
directions, then all four coupled unknowns with rebuilt state reconstructions
and separate equation checks. Omitting pressure-gradient or coefficient-velocity
sensitivity must fail. These steady affine interior checks do not establish
nonlinear convergence or boundary/transient consistency. A difference crossing
a limiter or donor switch does not test a single branch; neither a small fraction
of disagreeing nodes nor residual agreement establishes agreement of selected
linearizations at switches.

\paragraph{Accumulation cost.}
Table~\ref{tab:scatter} switches accumulation within one compiled sweep. A compiler
escape consumes every element result in both modes. Input staging and buffer
clearing remain; state gradients are reconstructed before timing. Atomic bypass
omits nodal additions; packed bypass omits local additions, owned/ghost draining
and ghost reduction. Every case passes finite, nonzero and bit-identical element
contributions, full-result agreement with normal execution within $10^{-11}$
relative infinity norm per equation, and zero bypass output.

At 72 threads, the first-order accumulation costs are
\SI{\scatterFoAtomicDelta}{\milli\second} for atomic and
\SI{\scatterFoPackedDelta}{\milli\second} for packed.
The limited scheme costs \SI{\scatterHoAtomicDelta}{\milli\second} and
\SI{\scatterHoPackedDelta}{\milli\second}, respectively. The differences account for
\scatterFoGapShare\% and \scatterHoGapShare\% of the respective full-probe layout gaps.
Normal execution in this allocation gives packed speedups of
$\scatterFoNormalSpeedup\times$ and $\scatterHoNormalSpeedup\times$.
Across the table, full-probe times differ from normal execution by
\scatterOverheadMin\% to \scatterOverheadMax\%.
The accumulation advantage persists at one thread, so it cannot be attributed solely
to contention between threads. These are marginal costs, including changes in memory
traffic and synchronization; the compiler escape can also affect scheduling. The
measurement supports accumulation as the main contributor to the gap in these probes,
without identifying an isolated atomic-instruction cost or a universal fraction of
production runtime.

\section{Discussion and conclusion}
\label{sec:discussion}
\label{sec:conclusion}

Ownership and a sorted gather remove atomics and colour barriers, with completion
between phases. Fixed inputs, packing and arithmetic fix summation order with
one thread per pack; colouring is also reproducible.
Probes show lower marginal accumulation costs; matched counters show comparable traffic.
The lagged action beats equivalent SpMV; exact Darwish does different work.
Benefits depend on terms, convection and packing, including the irregular-mesh
slowdown. Ordering and amortised setup are prerequisites; smaller topology does
not imply lower total memory.

Evidence covers these operators on one Grace CPU. Packed unstructured solver
performance, broader boundary/transient configurations and other architectures
remain open. Neither isolated atomic latency nor a universal bottleneck is established.
