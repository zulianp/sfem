\begin{abstract}
Performance work on matrix-free operators has concentrated on high-order discretisations, where
sum factorisation makes the element kernel cheap. Low-order unstructured operators have had less
of that attention and are commonly taken to be bandwidth-bound and therefore settled. The
measurements here show a substantial benefit from changing how element contributions
are accumulated. The layout's problem is the scatter: every element
contributes to nodes it shares with its neighbours, and that conflict is usually resolved with
atomics, which fix no summation order and leave the operator not bitwise reproducible; with
graph colouring, which adds a barrier per colour and reads back the destination it accumulates
into; or by assembling a sparse matrix, which takes the arithmetic out of the inner loop but
stores a matrix whose footprint grows with the stencil and streams it on every application.

We present a \emph{packed} mesh format that removes the conflict structurally. Each node is
owned by exactly one pack of elements and the owned ranges partition the node numbering, so a
pack accumulates into a private buffer and writes its owned rows out without contention; the
nodes it touches but does not own are closed by a gather that visits each destination once. No
atomic appears on any path, no barrier separates the packs, and the summation order is fixed by
stored index arrays rather than by thread arrival. The format is thus reproducible where atomics
are not, free of both costs colouring pays, and reads a mesh where the assembled operator stores
a matrix and streams it.

We evaluate it on the residual and matrix-free Jacobian action of a colocated CVFEM
Navier--Stokes discretisation on an NVIDIA Grace CPU. On \campDofs{} degrees of freedom the
packed residual reaches \campResPacked{}~MDOF/s against \campSpmvF{} for a sparse
matrix--vector product with the lagged matrix. The mesh the sweep reads is \fpImpl{}~bytes per
degree of freedom and the matrix the product streams \fpMatrixFSixFour{}; counting the sweep's
cached geometry and field vectors as well, its arithmetic intensity is \rlMfOverSpmv{} times the
product's. The Jacobian
action is reported in both forms, since they are not the same operator: lagged, it is what the
matrix holds, at $\jfLaggedVsF\times$ the product; differentiated, what a Newton--Krylov solve
applies, it costs $\jfExactCost\times$ and is $\jfExactVsF\times$. Most of the advantage is
present at one thread, where no contention exists, which places it in what the layout reads
rather than in the atomics it removes.
\end{abstract}

\section{Introduction}
\label{sec:intro}

Implicit solvers on unstructured meshes spend most of their time applying an operator. In a
matrix-free formulation that application is a loop over elements: gather the nodal values an
element needs, evaluate a small kernel, and scatter the result back to the element's nodes.
Elements share nodes with their neighbours, so on a shared-memory machine several threads reach
the same output location, and the resulting conflict must be resolved.

Three answers are in common use and each gives up something different. \emph{Atomic} updates
are the simplest and impose no structure on the mesh, but they serialise on contended nodes and,
more consequentially, they fix no order of summation. Floating-point addition is not
associative, so an operator applied twice to the same input returns two different answers.
\emph{Colouring} partitions the elements into conflict-free sets and removes the atomics, at the
cost of a barrier per colour and of accumulating into the destination, which has to be read
before it can be added to. \emph{Assembling} a sparse matrix removes
the problem from the inner loop entirely, but replaces a kernel that reads a mesh with a product
that streams a matrix, at a footprint that grows with the stencil rather than with the solution.
Section~\ref{sec:res:spmv} compares their work and traffic estimates, with the measurement and modelling limits made explicit.

What bitwise reproducibility buys is worth stating, because it is a property of the operator
rather than a convenience. An operator whose summation order is fixed is a function of its input,
and three things follow in a parallel environment. The result is the same at every thread count,
so a run on 72 threads can be reproduced exactly on one and examined there, in a debugger,
instead of by reasoning about interleavings. A regression test compares bits; an operator that
reorders needs a tolerance wide enough to absorb the reordering, and such a tolerance absorbs
defects as well. And an
experiment layered above the operator, whether a preconditioner, a scheme comparison or a scaling
study, measures the change under test alone; inside a Krylov method a perturbation at the last
bit reaches the iteration count and therefore the runtime, so without a fixed order the thread
count is a variable of the numerics as well as of the schedule.

We remove the scatter conflict in the data layout rather than resolving it by synchronisation. In
the \emph{packed} format, elements are grouped into packs, every node is owned by exactly one pack,
and the owned ranges partition the node numbering. A pack accumulates into a private buffer with
ordinary addition and writes its owned rows out without conflict, since no other pack owns them;
nodes it touches but does not own are staged and closed by a gather whose graph is built by
sorting, so each destination is visited by exactly one row in a fixed order. No atomic appears on
any path, and each node's summation order is fixed by index arrays rather than by thread arrival,
making the result bitwise identical at every thread count.

\noindent\textbf{Contributions.}
\begin{itemize}
  \item A mesh format whose ownership structure makes the matrix-free scatter
        \emph{atomics-free by construction} rather than by synchronisation, on any number of
        threads (\S\ref{sec:format}).
  \item An argument from three properties of the layout, with measurement, that operator
        application in this format is \emph{bitwise reproducible} at every thread count
        (\S\ref{sec:apply}, \S\ref{sec:res:determinism}).
  \item An evaluation on a solver's operators against an atomic sweep and against lagged
        sparse matrix--vector products, reported along a \emph{term-completeness ladder} and
        across convective schemes, so that the quoted margin is the one a solver sees
        (\S\ref{sec:res:throughput}).
  \item An investigation of pack-size optimality, identifying \emph{packs per thread} as the
        quantity that sets it, invariant to problem size and to the kernel's arithmetic, and
        giving a default derived from the core count (\S\ref{sec:res:packsize}).
\end{itemize}

\section{Related work}
\label{sec:related}

\paragraph{Matrix-free operator application.} Evaluating an operator from its element
contributions rather than from an assembled matrix is long established for high-order
discretisations, where the assembled stencil grows quickly with the polynomial degree and sum
factorisation makes the element kernel cheap~\cite{Orszag1980,DevilleFischerMund2002,Brown2010}.
Modern libraries build on that lineage and make the matrix-free operator the primary
object~\cite{KronbichlerKormann2012,KronbichlerKormann2019,MFEM2021,libCEED2021,Kolev2021}, as
do the form compilers that generate the element kernels~\cite{KirbyLogg2006,Firedrake2016}. That
work is largely concerned with making the kernel fast, and at high order the kernel is what
there is to make fast. At low order the kernel is small to begin with: sum factorisation applies
to a hexahedron and the kernels measured here use it, but its saving grows with the polynomial
degree, so at degree one it is a constant factor on an already short kernel. What is left is the
traffic and the scatter around it. This paper is concerned with those: the gather that stages an
element's nodal values and the scatter that returns its result, which bracket the kernel in the
loop body. The controlled accumulation study in \S\ref{sec:res:spmv} measures the benefit of this change.

\paragraph{Resolving the scatter.} The conflict between elements sharing a node is classically
resolved either by atomic updates or by colouring the elements so that no two of a colour share
one, and the trade between them has been studied most closely on GPUs, where Cecka et
al.~\cite{CeckaLewDarve2011} set out the alternatives and their costs. The present work differs
in where the resolution happens: colouring partitions the \emph{work} so that conflicting
updates never coincide in time, while the packed format partitions the \emph{data} so that
conflicting updates do not exist. We measure against colouring throughout, and report that it is
also atomics-free and, on this operator, also reproducible --- what separates the two is the
synchronisation it must pay and the traffic its accumulation costs.

\paragraph{Locality by spatial ordering.} Reordering an unstructured mesh along a space-filling
curve is standard practice for locality and for partitioning~\cite{Bader2013,Zumbusch2001}. The
distinction is that the packed format does not merely \emph{benefit} from such an
ordering: because a pack is a contiguous range of element indices, an unordered mesh gives packs
whose node sets are large and scattered, and the format's advantage disappears.
\S\ref{sec:res:ordering} measures what removing the ordering costs.

Graph partitioning addresses the same quantity more directly. Spectral
bisection~\cite{PothenSimonLiou1990} and the multilevel schemes that followed
it~\cite{KarypisKumar1998,PellegriniRoman1996} minimise the cut between parts, which is what a
pack's ghost count is, and renumbering the elements by part makes the parts contiguous ranges and
so admissible packs. The space-filling curve is used here because one pass yields the ordering
and the locality together.

\paragraph{Reproducibility.} Reproducible summation obtains a result that does not depend on the
summation order, through arithmetic --- compensated, extended or exactly-rounded accumulation~\cite{DemmelNguyen2013} ---
and pays for it at run time. This paper takes the opposite route: it does not make the sum
independent of its order, it fixes the order, in the index arrays the layout already stores. The
two are complementary rather than competing, and the distinction matters for cost, because
fixing an order is free once the layout has done it.

\paragraph{Prior art.} Blocking elements with locally numbered nodes is not novel, nor is
space-filling reordering; what they achieved is the question. Reguly and
Giles~\cite{RegulyGiles2015} block a grid into geometrically close elements and renumber their
degrees of freedom, reaching $10\times$ a two-socket 12-core CPU on a GPU --- but the blocking
buys locality alone, and the write conflict is still colouring or atomics, their CPU baseline
being block-coloured. Settgast et al.~\cite{Settgast2023} make the low-order matrix-free case on
GPUs with the same standard scatter. Wichrowski~\cite{Wichrowski2026} removes the scatter:
cell-wise storage, continuity closed by face exchanges at statically known offsets, no atomics
and no colouring, reaching \SI{14.1}{}~GDoF/s of unique degrees of freedom on a $\mathbb{Q}_1$
Laplace operator on an A100. The offsets are static because a macro-block's interior is
structured; at the interfaces between macro-blocks the method falls back to separate face, line
and vertex kernels over disjoint sets of degrees of freedom. And holding the cell-wise vector as
the primary representation stores a node once per incident element, which at $\mathbb{Q}_1$ is a
redundancy of about $8\times$ --- the degrees that amortise it are the high ones.

The two routes leave the same case open. Blocking takes the layout as far as locality and hands
the conflict back to colouring or atomics; removing the conflict outright has so far needed a
structured block interior to supply the offsets and a redundant representation that only high
order amortises. An unstructured mesh at low order offers neither.

That case is this paper's, and exclusive ownership is what takes it: a node belongs to one pack,
so there is no structured interior to depend on and no interface left over to treat separately,
and the remainder closes through a gather built by sorting. The gather is kept, so the vector
stays the size of the unique degrees of freedom --- the index traffic narrows instead of the
data multiplying. Atomics-freedom and reproducibility then follow from the layout rather than
from a reduction primitive, and that narrowed traffic is what pays for them. We measure against
element colouring as well, and \S\ref{sec:res:scaling} reports what it costs: less than its
usual framing suggests, because a colouring built greedily over a space-filling element order
leaves a colour's elements strided through the curve rather than scattered.

\section{The packed format}
\label{sec:format}

\subsection{Packs and reordering}

A \emph{pack} is a contiguous range of element indices together with the nodes those elements
touch: element $e$ belongs to pack $p = \lfloor e / n_{\mathrm{epp}} \rfloor$
(Figure~\ref{fig:decomposition}).

The mesh must be spatially reordered first, by a space-filling curve here, or a pack's elements
are scattered and the node set they touch is large; \S\ref{sec:res:ordering} measures the cost
of skipping it. Packing then renumbers the nodes in place, so everything indexed by node is
built after it --- the coordinates, and the sparsity pattern where a matrix is assembled at all.

\subsection{Node identity}
\label{sec:format:zones}

Each node has exactly one owning pack (Figure~\ref{fig:decomposition}), and pack $p$ owns a
contiguous, monotonically increasing
range of global indices. The owned ranges therefore \emph{partition} $[0, n_{\mathrm{nodes}})$.
Writing $n_c(p)$ for the size of that range, a pack-local index $\ell$ resolves to a global one
as
\[
  g(p,\ell) =
  \begin{cases}
    \texttt{owned\_nodes\_ptr}[p] + \ell, & \ell < n_c(p),\\[2pt]
    \texttt{ghost\_idx}\big[\texttt{ghost\_ptr}[p] + \ell - n_c(p)\big], & \ell \ge n_c(p).
  \end{cases}
\]
The ranges are contiguous and monotone because Algorithm~\ref{alg:build} numbers the packs in
order and advances a single cursor by $n_c$ (line~\ref{ln:advance}). An owner is therefore
recoverable by binary search, which is what lets a conflict graph over packs be built without
storing one.

The pack-local index is a \emph{16-bit unsigned integer}. That is the single most consequential
choice in the format and it cuts both ways: it halves the index traffic of the element sweep
against the \SI{32}{\bit} global index a flat sweep must use (\S\ref{sec:cost}), and it caps a
pack at $2^{16}$ distinct nodes. That cap is a correctness bound on the pack size;
\S\ref{sec:res:packsize} shows what should set it instead.

Within the owned range the indices are ordered \emph{non-shared first, then shared}, which is
what the two cursors of Algorithm~\ref{alg:build} produce (line~\ref{ln:cursors}). With $n_s(p)$
the number of a pack's owned nodes that some other pack also touches, the local index space
splits into three zones (Figure~\ref{fig:idspace}):
\begin{center}
\begin{tabular}{ll}
\toprule
range of $\ell$ & property \\
\midrule
$0 \le \ell < n_c - n_s$ & owned, touched by no other pack \\
$n_c - n_s \le \ell < n_c$ & owned, also touched elsewhere \\
$n_c \le \ell < n_{\mathrm{pack}}$ & ghost: touched, not owned \\
\bottomrule
\end{tabular}
\end{center}

The split earns nothing on a CPU, where one thread owns a pack and the whole flush of the owned
range is already contention-free. It is there for the case of several threads to a pack, where
the first zone can be written without synchronisation and only the shared tail cannot.

\subsection{Ghost lists and the reduction graph}
\label{sec:format:ghost}

A pack's elements contribute to nodes it does not own, and those contributions cannot go to the
global array: another pack owns the row. They are \emph{staged} instead, one slot per pack and
ghost node, and summed afterwards. Two things make this cheap. The slot is written by its pack
alone, so staging is a store and not a read-modify-write; and it is the minority path. On the
$n=\campN$ cube at the \fpPack-element pack size used throughout, those slots number
\fpGhostPct\% of the mesh's nodes, and the summation that empties them averages
\fpGhostPerRow{} terms per destination. Every owned row has gone straight to the global array
already.

The sum is taken over a \emph{reduction graph}, built by sorting (destination, slot) pairs and
grouping them (Algorithm~\ref{alg:build}, line~\ref{ln:sort}). Sorted pairs group into one row
per destination, so one thread owns each destination and no atomic is required, and within a
row the slots are visited in a stored order, so the sum is the same sequence of floating-point
additions on every run.

\subsection{Construction}
\label{sec:format:build}

Everything above is produced by five sequential passes over the connectivity,
Algorithm~\ref{alg:build}. The mesh is already spatially reordered when they start, and the only
parameter is $n_{\mathrm{epp}}$.

\begin{algorithm}
\caption{Building the packed format from a reordered mesh}
\label{alg:build}
\begin{algorithmic}[1]
\Statex \textbf{Pass 1 --- ownership}
\ForAll{packs $p$ in increasing order}
  \ForAll{nodes $v$ of the elements of $p$}
    \If{$v$ is unclaimed} \State $\mathrm{owner}[v] \gets p$ \label{ln:own}
         \Comment{first touch wins}
    \EndIf
  \EndFor
\EndFor
\Statex \textbf{Pass 2 --- sharing}
\ForAll{packs $p$, nodes $v$ of the elements of $p$}
  \If{$\mathrm{owner}[v] \neq p$} \State mark $v$ shared
  \EndIf
\EndFor
\Statex \textbf{Pass 3 --- renumbering} \Comment{$\mathrm{next} \gets 0$}
\ForAll{packs $p$ in increasing order}
  \State $n_c \gets |\{v : \mathrm{owner}[v] = p\}|$, \; $n_s \gets$ how many of those are shared
  \State $a \gets \mathrm{next}$, \; $b \gets \mathrm{next} + n_c - n_s$ \label{ln:cursors}
  \ForAll{nodes $v$ of the elements of $p$, first appearance only}
    \If{$\mathrm{owner}[v] = p$}
      \State $\mathrm{map}[v] \gets b{+}{+}$ \textbf{if} $v$ shared \textbf{else} $a{+}{+}$
    \Else{} \State charge one ghost slot to $p$
    \EndIf
  \EndFor
  \State $\mathrm{next} \gets \mathrm{next} + n_c$ \label{ln:advance}
\EndFor
\Statex \textbf{Pass 4 --- pack-local connectivity}
\ForAll{packs $p$, nodes $v$ in a node-major sweep of $p$'s elements}
  \If{$\mathrm{owner}[v] = p$}
    \State local id $\gets \mathrm{map}[v] - \texttt{owned\_nodes\_ptr}[p]$
  \Else
    \State append $\mathrm{map}[v]$ to $p$'s ghost list on first appearance; \label{ln:ghost}
    \Statex \hskip\algorithmicindent\hskip\algorithmicindent
            local id $\gets n_c(p) + (\text{its position there})$
  \EndIf
\EndFor
\Statex \textbf{Pass 5 --- reduction graph}
\State sort the pairs $(\mathrm{map}[v], j)$ over all ghost entries $j$ \label{ln:sort}
\State group by destination into \textsc{csr} rows
\end{algorithmic}
\end{algorithm}

Pass~1 makes ownership a function of the element order alone (line~\ref{ln:own}): a node goes to
the pack holding the lowest-indexed element incident on it, which is the node colouring of
Figure~\ref{fig:decomposition}. A node outside the packable prefix is claimed by no pack, keeps
its number and appears only as a ghost, which the format represents at an arbitrary global index
anyway.

Pass~3 creates both orderings of \S\ref{sec:format:zones} in one sweep, and a third that the
structure does not show: ids are issued on first appearance, so nodes adjacent in the element
sweep are adjacent in memory.

Pass~4 produces the only array the element sweep reads. The construction is linear in the
connectivity apart from the sort in Pass~5, and runs once per mesh, so its cost is amortised
over every application that mesh sees (\S\ref{sec:discussion}).

Figure~\ref{fig:reduction} draws both phases over the whole mesh: Phase~1 writes each pack's
owned rows straight to the global field and stages only its ghost contributions, and Phase~2
empties the staging buffer one row at a time, so the close is a single global pass rather than
an exchange between neighbouring packs.

\section{Operator application}
\label{sec:apply}

\subsection{The two-pass algorithm}

The apply runs in the two phases of Figure~\ref{fig:reduction}: a parallel pass over packs,
then a parallel pass over the rows of the reduction graph.

\begin{algorithm}
\caption{Packed operator application}
\label{alg:apply}
\begin{algorithmic}[1]
\Statex \textbf{Phase 1 --- local accumulation}
\ForAll{packs $p$ \textbf{in parallel}}
  \State $A \gets 0$ \Comment{pack-private accumulator, $n_{\mathrm{pack}}(p)$ rows}
  \State gather the input fields into pack-local order
  \ForAll{elements $e$ of $p$, in increasing index}
    \State evaluate the element kernel
    \State $A[\,\text{local node}\,] \mathrel{+}= \text{contribution}$
           \Comment{plain addition, no atomic}
  \EndFor
  \State \textbf{write} $A[0 \ldots n_c)$ to the global array \Comment{assignment, not
         accumulation}
  \State \textbf{store} $A[n_c \ldots n_{\mathrm{pack}})$ into the staging buffer
\EndFor
\Statex \textbf{Phase 2 --- gather}
\ForAll{reduction rows $r$ \textbf{in parallel}}
  \State $\text{global}[\texttt{dest}[r]] \mathrel{+}= \sum_{j \in \text{row } r}
         \text{staged}[j]$
\EndFor
\end{algorithmic}
\end{algorithm}

Both writes out of Phase~1 are assignments, and the ownership partition is why. The owned rows
are \emph{assigned} because no other pack owns them, so the global array never has to be zeroed
and a full pass over the output disappears; the staged values are \emph{stored} because a given
pack and ghost own that slot between them.

The input is read differently too. A flat element sweep reads a node once per incident element,
the packed sweep once per pack node --- on a hexahedral mesh about an eighth as many reads, and
contiguous for the owned majority.

\subsection{Reproducibility}
\label{sec:apply:determinism}

Floating-point addition is not associative, so a reproducible result requires a fixed summation
order, and any fixed order will do. Three properties fix it here, one per path a contribution
can take:

\begin{enumerate}
  \item \emph{Within a pack}, one thread walks the pack's elements in increasing index order,
        and pack membership is a pure function of the element index. The order in which a node
        receives its contributions from inside the pack is therefore the same on every run and
        at every thread count.
  \item \emph{Across packs, for owned nodes}, there is no summation to order at all: the owned
        ranges partition the node numbering, so exactly one pack contributes.
  \item \emph{Across packs, for shared nodes}, the reduction graph fixes the order, because
        each destination is one row and the row's terms are visited in a stored sequence.
\end{enumerate}

\noindent
Every path is atomic-free, and by the ownership partition rather than by a choice of
synchronisation primitive.

\paragraph{Scope of the claim.} The argument holds where one thread owns a pack, which is the
setting of this paper. Splitting a pack across threads leaves the reduction graph deterministic
and the in-pack accumulation open, so such an implementation would need its in-pack order fixed
too --- by gathering per node from a pack-local node-to-element adjacency, for instance, rather
than scattering per element. The property belongs to the execution together with the format.

\subsection{Alternatives}
\label{sec:apply:alternatives}



The packed layout is measured against two alternatives, which give up different things.

\paragraph{Atomic.} The flat sweep addresses nodes globally and resolves every collision with an
atomic update. It imposes no structure on the mesh at all, which makes it the natural reference
implementation, and it needs the output array zeroed first because it accumulates into it. The
atomic instruction is not what it costs --- \S\ref{sec:res:scaling} shows the sweep scaling
respectably --- what it costs is the summation order, and with it the operator's bitwise
identity across runs.

\paragraph{Colouring.} Partitioning the packs so that no two packs of a colour share a node lets
each colour write to the global arrays directly, with neither atomics nor a reduction, at the
cost of a barrier between colours. It shares the packed layout's gather and its pack-local
indexing, and differs from it only in how the result leaves the pack, which is what makes the
pair a controlled comparison in \S\ref{sec:res:scaling}.

\paragraph{Element colouring.} Colouring the \emph{elements} instead, so that no two of a
colour share a node, is what the literature means by the term, and it is the baseline the
packed layout should be measured against rather than only the pack colouring above. Elements are
renumbered into colour order, which makes a colour a contiguous range, so the sweep is the atomic
sweep with the element loop bounded one colour at a time and the atomic updates replaced by plain
addition; the lane blocking, the geometry gather and the element kernel are the same code, and
what the comparison separates is the scatter and not the kernel. The nodal gradient
reconstruction follows the same colouring, since it is a scatter over elements like any other
pass.

Two expectations about it do not survive the measurement, and \S\ref{sec:res:scaling} reports
both. It is reproducible, across repeats and across thread counts, for the same reason the packed
layout is: each node takes exactly one contribution per colour, so the colouring fixes the
summation order --- and the colouring depends on neither the thread count nor a pack size. And
the locality it is supposed to give up is largely intact, because the colouring is greedy over an
already space-filling element order, so a colour's elements are strided through the curve rather
than scattered.

Colouring is also bitwise reproducible here (\S\ref{sec:res:determinism}), with three
qualifications. The order it fixes belongs to the colouring, so reproducibility requires the
colouring to be constructed deterministically --- a property of the construction, not of the
layout. The number of colours is set by the decomposition rather than chosen (\campNColors{}
here, balanced to \campColorPacksLo{}--\campColorPacksHi{} packs), so the barrier count per
application is fixed while the work between barriers shrinks as threads are added. And writing
into the global arrays means accumulating into them: a node owned by one pack also receives from
packs in earlier colours, so the destination is read before it is added to, where the packed
layout's owned rows have a single writer. That is a cost of the scatter rather than of the
synchronisation, and it is measurable --- \colBytesPctResRc\% more DRAM per degree of freedom on
the residual, \colBytesPctJac\% on the bare Jacobian action (\S\ref{sec:res:spmv}).

\section{Cost model}
\label{sec:cost}

\subsection{What each representation must read}

The three representations differ less in arithmetic than in what they must move to reach it, and
the differences are structural enough to predict an ordering before any of them is run.

\paragraph{Indices.} A flat element sweep addresses its nodes globally, so it reads one
$\SI{4}{\byte}$ index per element--node incidence --- $\SI{32}{\byte}$ per hexahedron. Inside a
pack the same connectivity is expressed in pack-local indices, and because a pack may not
address more distinct nodes than its \SI{16}{\bit} index admits, those are $\SI{2}{\byte}$
wide. The
index traffic of the element sweep is therefore halved outright. This is not a compression trick
with a decode cost: the narrower index is the one the kernel indexes with.

\paragraph{Input.} As \S\ref{sec:apply} notes, the packed sweep reads a node's input once per
\emph{pack node} rather than once per element--node incidence --- eight times less for a
hexahedral mesh --- and contiguously over the owned majority, so a field held with a stride
inside an interleaved solution vector is read at the cost of a contiguous one.

\paragraph{Output.} Because the owned ranges partition the node numbering, a pack's owned rows
are \emph{written} rather than accumulated, so the global output array never has to be zeroed
and a full pass over it disappears from every application.

16-bit index halves the connectivity, \fpStd{} to \fpConn{}~B/dof, and the ownership and ghost
arrays spend part of that back: measured at \fpPack{} elements per pack
(Table~\ref{tab:footprint}), the packed topology is \fpImpl{} against \fpStd{}~B/dof, or
\fpImplPct{}\%. Two items account for nearly all the gap to what the format costs in principle.
The permutation between packed and unpacked numbering is \fpNodeMap{}~B/dof and the apply never
reads it (\fpWorkingPct{}\% without it); and the reduction graph's two offset arrays are 64-bit
while indexing under a million entries, so narrowing them --- which their own lengths permit
with three orders of magnitude to spare --- saves \fpReduceSaving{} more and reaches
\fpFloorPct{}\%, or \fpFloorBigPct{}\% at \fpPackBig{} elements per pack where ghosts are
proportionally fewer. Neither narrowing is applied, so Table~\ref{tab:footprint} carries

Coordinates are byte-identical in both and excluded; with them the ratio is \fpImplPtsPct{}\%.

The sharper contrast is with assembly. A sparse matrix--vector product does little arithmetic per
byte, so its rate is set by how much it must read, and what it reads is a stencil: $4\times4$
blocks whose count grows with the connectivity. The matrix-free side reads the mesh itself, and
Table~\ref{tab:footprint} puts the gap at more than two orders of magnitude, essentially
independent of problem size.

\paragraph{Operator equivalence.}
An assembled Jacobian cannot carry the Rhie--Chow pressure-gradient sensitivity: the exact
Jacobian differentiates through the nodal gradient reconstruction, so it needs the reconstructed
gradient of the \emph{direction}, and putting that into a matrix would couple pressures beyond
nearest neighbours and destroy the one-ring sparsity the matrix is built on. The matrix therefore
\emph{lags} that term, so a matrix-free action carrying it does strictly more work than the
matrix encodes, and comparing the two as one operator overstates the \textsc{bsr} matrix's
effectiveness. The two forms are $\Jex$ and $\Jlag$ of \S\ref{sec:setup}, and
Table~\ref{tab:jacfair} reports both; only $\Jlag$ is what the matrix holds.

The assembled operator stores values for the full stencil, while the matrix-free
operator reads the mesh, cached geometry and field vectors. The bare-kernel work and
traffic models give an intensity ratio of \rlMfOverSpmv{} against the lagged product.
Section~\ref{sec:res:spmv} states the limits of that comparison; it does not establish
a hardware bottleneck or a full-operator efficiency.

\paragraph{Method.} The bandwidth is a STREAM triad,
compiled with \texttt{gcc -O3 -fopenmp -mcmodel=large} over arrays of $80\times10^{6}$ doubles
--- about \SI{1.9}{\giga\byte} in three arrays, some sixteen times the shared L3, so the triad
genuinely streams. The FP64 rate is the best of five timed $N=8192$ double-precision \textsc{gemm}
calls into \emph{OpenBLAS 0.3.28}, the threaded build the same node resolves for the solver;
at that size the operational intensity is of order $10^3$~FLOP/byte, so the kernel is
unambiguously compute-bound and the figure is a sustained rate rather than a peak. Five
repetitions agreed to \SI{0.2}{\percent}.

The triad reports useful array bytes per second, while SCF counters report memory
traffic, including any write allocation~\cite{StreamAccounting}. These conventions
require calibration before a ratio can be read as hardware efficiency. The DGEMM
rate is a measured reference, not a universal compute ceiling. A nominal FP64 peak would additionally require a verified operating clock.

One further detail of the bandwidth figure: it is quoted at the thread count the kernels run at,
which is not where it peaks. The triad reaches \SI{\streamPeak}{\giga\byte\per\second} at
\streamPeakThreads{} threads and falls to \SI{\streamTriad}{\giga\byte\per\second} at
\streamThreads{} --- the memory system saturates before the socket does, so the last half of the
cores add compute but no bandwidth. We use the \streamThreads{}-thread figure throughout,
as the reference for that thread count, without assuming identical bandwidth on every node.

\paragraph{The case.} The operators are those of a colocated control-volume finite element
discretisation of the incompressible Navier--Stokes equations on hexahedra. Four unknowns live
at each node --- three velocity components and pressure --- and fluxes are integrated over the
sub-control-surfaces of the dual mesh. The discretisation itself is not the subject of this
paper, but \emph{which} operator is being measured is, so the variants are set out explicitly.

\paragraph{Geometry.} Every rate in this paper is for \emph{affine} element geometry: one
Jacobian per element, its adjugate and determinant built once at setup, which is exact on the
structured hexahedral meshes measured. The isoparametric variant is implemented and selectable but
is not measured here, and no rate below applies to it; the gap is largest on the nodal
reconstruction of \S\ref{sec:res:hoexact}, where per-element geometry is exactly the work the
affine sweep amortises over all its fields.

\paragraph{Convective schemes, reconstruction, and the exact Jacobian.} The baseline flux is
\emph{first-order upwinding with a hard donor switch}: the face value is taken from whichever
side the mass flux comes from, with no blending band.

The higher-order flux is a \emph{deferred
correction}~\cite{KhoslaRubin1974,XuePhanThienTanner2002}. The face value is reconstructed from
the donor node and its nodal velocity gradient,
$u_{\mathrm{face}} = u_{\mathrm{donor}} + \nabla u_{\mathrm{donor}}\cdot
 (x_{\mathrm{scs}} - x_{\mathrm{donor}})$,
and the scheme adds its \emph{difference} from the first-order value. The first-order flux is
carried implicitly and that difference explicitly, which is the method's point: the implicit
operator stays the diagonally dominant first-order one, and stays the same whichever
higher-order scheme is chosen. Four variants are built: the unlimited reconstruction and three
limiters, Barth--Jespersen, Venkatakrishnan and Darwish--Moukalled.

The nodal gradient the reconstruction reads is a separate pass over the mesh. It is assembled
from the element gradients incident on a node and completed by a ghost reduction, and it is the
same pass that supplies the Rhie--Chow coupling its pressure gradient.

Both the correction and the coupling can be differentiated or held fixed, independently. Held
fixed --- \emph{lagged} one Newton step --- the gradient is an input to the application rather
than part of it. Differentiated, the Jacobian action needs the reconstructed gradient of the
\emph{direction} and not only of the state, which is one further pass per operator
application. All four
combinations are implemented and measured (\S\ref{sec:res:hoexact}). Here ``exact'' means
that all reconstruction and flux sensitivities are retained on differentiable branches.
At limiter ties or a zero mass flux, the action uses the implemented tie conventions;
a classical Jacobian need not exist. In particular, writing a convective flux as
$m^+ u_L + m^- u_R$, with $m^\pm=(m\pm|m|)/2$, shows that its two derivatives at
$m=0$ differ when the reconstructed states $u_L$ and $u_R$ differ. Roundoff can then
select different branches in two layouts even when their residuals agree.

\paragraph{Operators.} The names below are used throughout, in the tables and figures as well as
the text. The subscript is the Rhie--Chow term, whose sensitivity is to the pressure gradient,
and the superscript the deferred correction, whose sensitivity is to the velocity gradient. The
two are independent, so a symbol states which differentiations the measured operator carried.

$\Gop p(u)$ and $\Gop u(u)$ are the nodal reconstructions of the pressure gradient (3
components) and the velocity gradient (9) at the state $u$, and $\Gop p(v)$, $\Gop u(v)$ the
same reconstructions of a Krylov direction $v$. Each is one element sweep and one ghost
reduction.

$\Fres(u)$ is the residual with first-order upwinding and $\Fho(u)$ the residual with the
deferred correction. Both carry the Rhie--Chow coupling and so read $\Gop p(u)$; $\Fho$ reads
$\Gop u(u)$ as well.

Three Jacobian actions are measured. $\Jex(u)\,v$ is
the exact Jacobian of $\Fres$: it differentiates the coupling through the reconstruction and so
rebuilds $\Gop p(v)$ on every application. $\Jhoex(u)\,v$ is the exact Jacobian of $\Fho$, adding
the differentiated correction and the derivative of the limiter, and rebuilding $\Gop u(v)$ with
it --- in the same sweep as $\Gop p(v)$, since the two read different fields of one array at one
stride. $\Jlag(u)\,v$ lags both: it evaluates the coupling with $\Gop p(u)$, drops its
sensitivity, and rebuilds nothing.

$\Jlag$ is what that implicit treatment gives: the correction is an explicit source, so it
contributes nothing to the operator, which is why a single matrix serves every scheme and why
$\Jlag$ is one operator rather than one per scheme. The price is that it is an
approximate linearisation of $\Fho$: for the unlimited correction, $\Jhoex$ agrees with a
finite difference to \hoxFdUnlim{} where $\Jlag$ differs by \num{6e-2}
(\S\ref{sec:res:hoexact}). An approximate Jacobian can still converge to a root of $\Fho$;
these action checks do not establish nonlinear convergence. Between them sits a partially
implicit treatment: the correction's derivative splits into the mass-flux sensitivity times the
increment at $\Gop u(u)$, which needs no direction reconstruction, and the increment's own
derivative at $\Gop u(v)$, which does, and keeping only the first is neither form measured here.

With the higher-order correction treated as an explicit source, $\Jex$ is also the
correction-lagged, RC-exact action. It is an approximate derivative of $\Fho$, and an exact
derivative of the surrogate residual with that source held fixed.

Caching a reconstruction at the current state is distinct from dropping its sensitivity.
For $F(u)=\mathcal{R}(u,g(u))$, differentiation gives
$F'(u)v=\mathcal{R}_u v+\mathcal{R}_g g'(u)v$ wherever the derivatives exist.
During a Krylov solve, $u$ is fixed: $g(u)$ can be reused while $g'(u)v$ is evaluated for
each direction. Both terms are retained in the exact action. The state cache must be
refreshed when the state or geometry changes.

The assembled matrix holds $\Jlag$ alone, for the sparsity reason of
\S\ref{sec:cost}. Algorithm~\ref{alg:jacaction} is where the forms part, and the driver
records which one ran.

\begin{algorithm}
\caption{Jacobian action: $\Jex$, $\Jhoex$ and $\Jlag$}
\label{alg:jacaction}
\begin{algorithmic}[1]
\Require state $u$, direction $v$; $\Gop p(u)$, and $\Gop u(u)$ when the correction is carried,
         both hoisted from the Newton step. Exact by default
\Ensure $\Jex(u)\,v$, or $\Jhoex(u)\,v$ when the correction is carried; $\Jlag(u)\,v$ when lagged
\If{exact}
  \State $q, g_v \gets \Gop p(v)$, and $\Gop u(v)$ if the correction is carried
         \Comment{\emph{one} sweep of Algorithm~\ref{alg:apply}: $1$ scalar field, or $4$ at the same
                  stride}
\Else
  \State $q, g_v \gets \varnothing$
         \Comment{lagged: the correction stays an explicit source, as deferred correction intends}
\EndIf
\State apply Algorithm~\ref{alg:apply}, whose element kernel linearises the first-order
       convective flux about $u$ in direction $v$, adds the viscous term, and adds the
       Rhie--Chow coupling, read from $\Gop p(u)$ and differentiated through $q$ when $q$ is
       present
\If{$g_v \neq \varnothing$}
  \State the same kernel adds the differentiated deferred correction: the mass-flux sensitivity
         times the limited increment at $\Gop u(u)$, plus the increment's own derivative --- the
         limiter's included --- at $g_v$
\EndIf
\State add the boundary closure and the transient term, each an extra sweep
\Statex The exact forms require one reconstruction of the \emph{direction} per operator application:
        $\Gop p(u)$ and $\Gop u(u)$ are hoisted across
        the Krylov solve because $u$ is fixed there, while $\Gop p(v)$ and $\Gop u(v)$ change
        every iteration and cannot be cached across different directions.
\end{algorithmic}
\end{algorithm}

\paragraph{Pass structure.} The operators above differ structurally and not only in arithmetic.
A node's reconstructed gradient needs contributions from every element incident on it, so $\Gop$
must be \emph{complete} before any flux may use it. That is a data dependency, so the
reconstruction cannot fuse into the flux sweep: it is a separate pass ending in its own ghost
reduction. A state reconstruction is hoisted --- computed once per Newton step and reused across
the Krylov solve, since $u$ is fixed there --- and a direction reconstruction cannot be, because
the direction changes every iteration. This adds one reconstruction pass to $\Jex$ relative to
$\Jlag$ in Table~\ref{tab:passes}, as well as derivative arithmetic in the flux kernel.

earlier implementation, which also rebuilt the state gradients inside each application:
two scalar input fields for $\Jex$ and eight for $\Jhoex$, fused in one sweep. The benchmark
retains this scope through \texttt{--rebuild-state-gradients}; its default now caches the

implementation. A performance comparison requires new runs with the mode recorded.

The driver times that sweep separately, so its share of the application appears beside the
element kernel's rather than folded into it.

\paragraph{The solver's terms.} The Rhie--Chow coupling~\cite{RhieChow1983} is required: a
colocated discretisation without it admits the checkerboard pressure mode, so every operator a
solver applies carries it, and $\Fres$, $\Fho$ and all four Jacobian forms above are defined with
it. The boundary closure over boundary sub-control-surfaces and the transient mass term are
likewise part of the operator the solver applies. All three are nonetheless \emph{switchable} in
the code, which is what makes the completeness ladder of \S\ref{sec:res:ladder} possible: it adds
them one at a time to attribute cost to each. The bare element kernel at the bottom of that
ladder is a measurement configuration and not an operator.

\paragraph{Problem sizes.} Sizes run from $n=64$ to $n=192$ on a cube, \SI{1.1e6}{} to
\SI{2.9e7}{} degrees of freedom. The smaller sizes make the saturation knee visible rather than
being compared across layouts; every cross-layout statement is drawn at $n\ge128$, where the
packed residual has saturated.

\paragraph{Measurement protocol.} The layout timing campaigns interleave their arms within each allocation.
The roofline combines separate timing, traffic and reference runs; it is an exception
to a comparison on one node, as Table~\ref{tab:roofline-sources} makes explicit. This is not a
formality: node-to-node variation here is 5--11\%, larger than several differences the paper
discusses, and a change already shown performance-neutral by a controlled comparison once read
5.7--6.5\% slower with its two sides on different nodes. Each recorded run also carries the
configuration that \emph{dispatched}, not the one requested, so a measurement cannot claim a
term the code path silently dropped.

\subsection{Reproducibility}
\label{sec:res:determinism}

Measured at $n=\detN$ over $\detRepeats$ repeats at 72 threads and over one run at each of
$\detThreads$ threads, the atomic sweep agrees with itself in none of the runs: the repeats give
$\detAtomicresRep$ distinct results and the thread counts $\detAtomicresThr$, on the residual and
on the Jacobian action alike. The packed layout gives a single answer in both sweeps, at every
thread count and for both operators.

Both colourings are reproducible here as well, across repeats and across thread counts, as is the
packed layout; all three avoid atomics and so fix a summation order, and they differ in
throughput (\S\ref{sec:res:throughput}). The element-coloured layout fixes its order without a
pack at all: each node takes one contribution per colour, and the colouring depends on neither
the thread count nor a pack size. Two caveats attach to
the colouring result: its reproducibility depends on the colouring being constructed
deterministically, which is a property of the construction rather than the layout, and agreement
over seven runs is evidence rather than proof.

Reproducibility is measured with a fingerprint folding every output value's bit pattern. A
checksum is a running sum over millions of values, so a last-bit difference on a few nodes falls
below the total's unit in the last place: on this operator a checksum reported two runs identical
where a per-node comparison showed hundreds of differing doubles. Fingerprints are compared only
within a layout, since packing renumbers the mesh; operator equivalence across layouts is
established separately, by matching nodes on coordinates.

\subsection{Thread scaling}
\label{sec:res:scaling}

\paragraph{Single thread.} The packed and coloured sweeps reach \scalePackedResOne{} and
\scaleColoredResOne{}~MDOF/s, equal to each other, against \scaleAtomicResOne{} for the atomic
sweep. All three sweeps are lane-blocked over the same element group and call the same
element kernel. One thread excludes contention between threads, but atomic additions
still have a cost. The factor of $\scaleResLayoutOne$ therefore does not isolate
pack-local input staging or narrower indices from output accumulation.
Table~\ref{tab:scatter} measures the latter in a separate controlled experiment.

\paragraph{Atomic scaling.} The atomic sweep reaches $\scaleAtomicResSpeedup\times$ on 72 threads,
an efficiency of \scaleAtomicResEff\%, above the packed layout's \scalePackedResEff\%.
This scaling does not show a growing parallel-efficiency penalty for the atomic sweep
over the measured range, but it cannot quantify contention by itself. The accumulation
diagnostic shows that a substantial atomic-layout cost is already present at one thread.

\paragraph{Colouring, of packs and of elements.} Measured on the same sweep but left off the
figure. The pack-coloured layout starts level with the packed one --- \scaleColoredResOne{}
against \scalePackedResOne{}~MDOF/s --- and ends at \scaleColoredResTop{} against
\scalePackedResTop{}, \scaleColoredResEff\% efficiency against \scalePackedResEff\%. The two run
the same packs, staging and element kernel, so the gap is entirely in how the result leaves the
pack: \campNColors{} barriers per application, which cost nothing at one thread, and an
accumulation that reads the destination back, which costs \colBytesPctResRc\% in traffic at every
thread count.

Element colouring is the one the literature means, and it costs less than its framing suggests.
At one thread it reaches \scaleEcolorResOne{}~MDOF/s against the packed layout's
\scalePackedResOne{} --- the locality a pack-based sweep is credited with is largely intact,
because the colouring is greedy over an already space-filling element order and a colour's
elements are therefore strided through the curve rather than scattered. That is \scaleEcolorOfPackedOnePct\% of the packed
layout's single-thread rate and $\scaleEcolorOverAtomicOne\times$ the atomic sweep's.
Element colouring thus recovers a substantial part of the packed rate while using standard
connectivity; it changes accumulation and traversal order together, so it does not isolate
index width. At 72 threads it reaches
\scaleEcolorResTop{} against the pack colouring's \scaleColoredResTop{}, and scales better than
either pack-based layout --- \scaleEcolorResEff\% efficiency against \scalePackedResEff\% and
\scaleColoredResEff\%. Its sweep has no ghost reduction or pack-local staging, but retains
colour barriers. The Jacobian action behaves the same way, \scaleEcolorJacTop{}~MDOF/s at
\scaleEcolorJacEff\% efficiency.

\paragraph{Packed efficiency.} The unit of parallel work is the pack, and there are
\scalePacks{} of them for 72 threads, \scalePacksPerThread{} each, so static scheduling
quantises the imbalance in steps of the reciprocal of that before any variation in per-pack cost. That is a
statement about the pack size, and \S\ref{sec:res:packsize}
takes it up.

\subsection{Pack size and the index-type ceiling}
\label{sec:res:packsize}

\begin{figure}[t]
  \centering
  \input{figures/packsize}
  \caption{Throughput of $\Jex$ with the boundary closure against packs per thread, at two
    problem sizes. Solid: first-order upwinding. Dashed: $\Jhoex$ with the Darwish--Moukalled
    limiter. The pack size is the
    knob; packs per thread is the axis on which the collapse is explained.}
  \label{fig:packsize}
\end{figure}

The pack size is the one parameter of the format, and what selects its default is not what
should. A pack may address no more distinct nodes than its index type admits, and the packer
sizes packs against that ceiling using the pessimistic bound (elements $\times$ nodes per
element), which credits no sharing at all. For hexahedra that yields roughly
$\packLargeCeil{}$ elements per pack. But a pack is one unit of parallel work, so the number of
packs \emph{is} the available parallelism, and an index-width ceiling knows nothing about how
many cores the machine has.

At $n=\packLargeN{}$ the ceiling-derived pack leaves $\packLargeCeilPacks{}$ packs for 72 threads
and gives up $\packLargeCeilLoss\times$ against the best size (Figure~\ref{fig:packsize}). At
$n=\packSmallN{}$ it leaves $\packSmallCeilPacks{}$ packs, \packSmallCeilPpt{} per thread, and
throughput falls by $\packSmallCeilLoss\times$. Plotted against packs per thread the two curves
fail together at the same place on this axis while failing at different pack sizes,
identifying parallel granularity rather than cache residency as the mechanism. Arithmetic does
not move the knee either: at \pkszHoWorkFactor$\times$ the work per degree of freedom the limited
higher-order arm falls at the same place, retaining \pkszKneeHo{} of its pre-knee rate against
\pkszKneeFo{} for first order.

The default therefore derives from the core count, with the index-width ceiling retained as the
correctness bound it is: the packer targets \packsPerThread{} packs per thread and rounds to a
power of two, which reproduces the measured optimum at every size swept. Every measurement in
this paper runs at that default rather than at the ceiling-derived one, so the numbers reported
are the ones the format gives when its one parameter is set from the machine.

\subsection{Spatial ordering}
\label{sec:res:ordering}

A pack is a contiguous range of element indices, so the element order decides which nodes it
touches. Replacing the space-filling pass with a lexicographic order at fixed pack size grows the
mean node set per pack from $\ordSfcMean{}$ to $\ordLexMean{}$, and costs
$\ordSfcRes{}\to\ordLexRes{}$~MDOF/s on the residual and $\ordSfcJac{}\to\ordLexJac{}$ on
$\Jex$, both carrying the boundary closure at $n=128$. The ordering is
a precondition of the format, as \S\ref{sec:format} states, rather than an optimisation applied
to it.

The correction adds a reconstruction and, where a limiter is selected, a limiter evaluation at
every sub-control surface, against a first-order flux of a branch and a multiply. Three limiters
are measured beside the unlimited reconstruction: Barth--Jespersen, which clips the
reconstructed face value into the range its two nodes span~\cite{BarthJespersen1989};
Venkatakrishnan, which smooths that clip into a rational function so a steady state can
converge~\cite{Venkatakrishnan1995}; and Darwish--Moukalled, which applies a
normalised-variable \textsc{tvd} limiter on an unstructured
mesh~\cite{DarwishMoukalled2003}. Table~\ref{tab:convho} and Figure~\ref{fig:convho} report all
five variants.

\paragraph{Scheme dependence.} The ratio falls with the arithmetic each scheme adds:
$\hoFirstLayoutRatio\times$ on first-order upwind, $\hoUnlimLayoutRatio\times$ with the unlimited
reconstruction, and $\hoLimLayoutRatioLo$--$\hoLimLayoutRatioHi\times$ across the three limiters,
which land within a few percent of one another. The correction adds arithmetic per
sub-control surface and changes the balance of work. These total-time ratios alone
do not identify which part of the layout advantage loses relative importance. The reconstruction itself is affine arithmetic on the element Jacobian --- the
node-to-centroid vectors are the Jacobian applied to constant reference offsets, so no coordinate
is read --- and the twenty-four node-to-surface increments are formed once per element before
the twelve face loops, which is why the unlimited arm costs the packed layout only
$\hoUnlimCostPacked\times$. The completeness ladder of \S\ref{sec:res:ladder} shows the same dependence across
physical terms.

The coloured sweep gives $\hoFirstColOverStd\times$ over the standard sweep at
first order and $\hoHoColOverStdLo$--$\hoHoColOverStdHi\times$ on the higher-order
arms. Packed over coloured falls from $\hoFirstPackedOverCol\times$ to
$\hoDmPackedOverCol\times$. These comparisons include colour barriers and
changes in memory-access order as well as accumulation. Similar coloured and
atomic times therefore do not establish that atomic updates are cost-free.
In the separate Darwish probe (Table~\ref{tab:scatter}), marginal accumulation
costs at 72 threads are \SI{\scatterHoAtomicDelta}{\milli\second} for atomic
and \SI{\scatterHoPackedDelta}{\milli\second} for packed. This supports a benefit
from packed accumulation in that tested case. These costs include memory and
synchronization effects and do not isolate atomic-instruction latency.

\paragraph{Cost of the correction.} Within the standard layout the unlimited reconstruction costs
$\hoUnlimCostAtomic\times$ and the limiters $\hoLimCostAtomicLo\times$ to
$\hoLimCostAtomicHi\times$; within the packed layout, $\hoUnlimCostPacked\times$ to
$\hoLimCostPackedHi\times$. The packed factors are larger because the layout has removed more of
the first-order cost, leaving the arithmetic it does not touch. The three limiters land close
together, $\hoLimCostPackedLo\times$ to $\hoLimCostPackedHi\times$ packed, and the step from the
unlimited reconstruction to the cheapest of them is about the size of the spread among them: all
three share the reconstruction and differ only in the function applied to the increment.

\paragraph{The same schemes in the Jacobian.} Figure~\ref{fig:jacho} repeats the sweep for the
action, which is the operator a Newton--Krylov solve applies once per linear iteration against one
residual per step. Two things differ from the residual. The absolute cost of differentiating the
correction is large --- \jachoFirstPacked{} to \jachoUnlimPacked{}~MDOF/s packed on the unlimited
arm alone, before any limiter --- because $\Jhoex$ reconstructs $\Gop u(v)$ on every
application,
nine components against the three $\Gop p(v)$ that $\Jex$ already rebuilds. And the format's margin moves the other way: it rises from
$\jachoFirstLayoutRatio\times$ to $\jachoUnlimLayoutRatio\times$ before the limiters pull it back
to $\jachoDmLayoutRatio$--$\jachoClipLayoutRatio\times$, since the added reconstruction is
itself packed and is the sweep the layout helps most, whereas a limiter derivative is arithmetic
at a sub-control surface that no layout can help with. Lagging the correction is the control
on all of this: that arm reproduces $\Jex$ to the last bit, at \jachoLaggedPacked{}~MDOF/s,
which is what a deferred correction means --- it reaches the residual and not the Jacobian.

\paragraph{Traffic with the correction.} Table~\ref{tab:residual-counters}
measures first-order and Darwish residuals with the same Rhie--Chow coupling
and cached state gradients. The correction reads the additional nine-component
velocity gradient and increases measured traffic in both layouts. These results
cover Darwish only; reading the same source arrays does not establish equal
traffic for every limiter, since spills and cache behaviour may differ.

\paragraph{Inherited properties.} The packed higher-order
sweep has the same shape as the first-order one: stage the pack's fields, accumulate into a
pack-private buffer with plain addition, write the owned rows straight out, close the ghosts
through the reduction graph. No atomic appears, and the summation order is fixed by the same
index arrays, so the reproducibility of \S\ref{sec:res:determinism} is a property of the
higher-order operator too and not something the scheme gives up.

\paragraph{Equivalence.} The two layouts are verified against one another node by node rather
than by checksum: the residual of this state sums to order \num{1e-14} and is almost all
cancellation, so a term can be present at every node and absent from the total. They agree to
\num{2e-17} on every arm, with and without the Rhie--Chow coupling.

\subsection{$\Jhoex$, the exact higher-order Jacobian action}
\label{sec:res:hoexact}

With the correction left an explicit source, $\Jex$ approximates the derivative of $\Fho$
(\S\ref{sec:setup}). $\Jhoex$ also reconstructs $\Gop u(v)$ and differentiates the limiter.
The measurements in this section use the rebuild mode: their fused sweep includes both
state and direction gradients, eight scalar input fields for $\Jhoex$ against two for
$\Jex$. Thus the measured cost includes redundant state reconstruction as well as the
additional sensitivities. In this mode, the unlimited arm reaches
\hoxExactPackedUnlim{}~MDOF/s against Venkatakrishnan's \hoxExactPacked{}, a factor of
$\hoxLimiterCost$.

$\Jhoex$ costs $\hoxCostPacked\times$ $\Jex$, \hoxLaggedPacked{} to
\hoxExactPacked{}~MDOF/s, against $\hoxCostAtomic\times$ on the standard layout. The two are close
but not equal, and should not be: the added work is a differentiated flux, whose cost is the same
arithmetic on either layout, plus the reconstruction, whose cost is not --- it takes a very
different share of the two applications, as below. The format's advantage survives the addition:
$\hoxLayoutLagged\times$ on $\Jex$ and $\hoxLayoutExact\times$ on $\Jhoex$. The added pass is
itself packed, gathering pack-locally and closing through the same ghost graph the operator
sweeps use.

\paragraph{Action traffic.} The historical Darwish action has estimated traffic
of \hoJacBytesPacked{} bytes per degree of freedom packed and \hoJacBytesAtomic{}
atomic. Its first-order action with Rhie--Chow has \foJacBytesPacked{} and
\foJacBytesAtomic{}, respectively. These captures predate the benchmark's
state-gradient cache correction. The element-work model omits reconstruction work,
so these points do not establish the full action's arithmetic intensity or the effect
of the cache correction.

\paragraph{The reconstruction.} Timed on its own it is the sweep the format helps \emph{most}:
the pressure gradient at \ngPgradPacked{} against \ngPgradAtomic{}~MDOF/s, a factor of
$\ngPgradRatio$, and the three-component velocity gradient at \ngUgradPacked{} against
\ngUgradAtomic{}, a factor of $\ngUgradRatio$ --- both far above the
\hoxLayoutLagged$\times$ the element sweeps get. Almost all of a reconstruction is indexed
traffic, with relatively little arithmetic. The standalone one- and three-field sweeps
do not measure the same work as the fused eight-field reconstruction in the recorded
$\Jhoex$ runs. Their throughput should not be used to infer its share of the action.
The recorded phase fractions also included warmup time in the reconstruction counter
but excluded it from total application time. The benchmark now resets both counters
before measurement; corrected phase fractions require new runs.

On the tested unlimited case, a finite difference of $\Fho$ with $\Gop u$ rebuilt at
each perturbed state agrees with $\Jhoex$ to \hoxFdUnlim{}, whereas the
correction-lagged action differs by \num{6e-2}. This does not validate all limiter
branches. For limited cases, a central difference that crosses a limiter or donor
switch is not a reference for the action's chosen branch. Validation must distinguish
such crossings from errors on unchanged branches; a small fraction of disagreeing
nodes alone does not establish correctness. The regressions require a relative infinity
error below \num{1e-6} at two prescribed step sizes on perturbed states. The first
checks velocity directions without Rhie--Chow coupling. A separate coupled check
perturbs all four unknowns, rebuilds the state reconstructions, and checks each
momentum and continuity equation separately. It also requires controls omitting the
pressure-gradient sensitivity or the coefficient's velocity sensitivity to fail.
These checks cover the tested steady, affine interior operators; they do not establish
nonlinear convergence or boundary and transient consistency. Residual agreement
between layouts also does not establish agreement of their selected linearizations
at a switch.

the atomic sweep is $\jfLaggedAtomicVsF\times$. Both beat the matrix, and the standard layout is
lane-blocked here like the others, so that margin is the method's rather than an artefact of how
the baseline was written --- but the layout more than doubles it. The case for matrix-free is
therefore made twice over, and the larger half of it is the layout.

$\Jex$ costs $\jfExactCost\times$ $\Jlag$ on the packed layout, its reconstruction sweep
appearing as throughput. Quoting $\Jex$ against the SpMV would report $\jfExactVsF\times$ rather
than $\jfLaggedVsF\times$, understating the matrix-free side by more than a quarter while
appearing to favour it; both are given because they answer different questions.

The $\Jhoex$ rows are where the comparison stops being one. Packed $\Jhoex$ lands
below the double-precision SpMV under both limiters: $\jfClipExactVsF\times$
(Barth--Jespersen), $\jfHoExactVsF\times$ (Darwish--Moukalled), the latter costing
$\jfHoCostExact\times$ its first-order self. Read as a throughput ratio that
is a loss, and it would be, if the matrix held the same operator. It cannot: the higher-order
correction differentiates through a nodal reconstruction, so the coupling it induces reaches
past the one ring the matrix's sparsity is built on, and assembling it would mean a different
and far larger matrix. The row therefore prices the higher-order scheme against the best the
assembled representation can offer \emph{at all}, which is a first-order operator, and what it
says is that the scheme costs about what that representation's whole advantage is worth. A
solver that wants $\Jhoex$ has no matrix to fall back on; the question is what it costs
matrix-free, and Table~\ref{tab:jacfair} answers that in the same units.

\section{Discussion and limitations}
\label{sec:discussion}

The spatial ordering is a precondition of the format, and its one-off cost is repaid by an
operator applied many times per mesh. The reproducibility claim is scoped to execution in which
one thread owns a pack (\S\ref{sec:apply:determinism}); colouring fixes a summation order as
well, and what the packed layout adds is that it removes the barriers with it. The margin
depends on the operator --- $\hoFirstLayoutRatio\times$ to $\hoDmLayoutRatio\times$ across
convective schemes, \ladderBare{} to \ladderFull{} across physical terms --- which is why the
results are reported along both axes rather than as one number, and it is the reason to measure
a format against the operator a solver applies. What is open is reach: one Grace die, and the
operators of one discretisation. Narrower index traffic, a gather in place of repeated indexed
reads, no zeroing pass and no atomics are specific to neither, so carrying the format to another
architecture and to discretisations beyond colocated CVFEM Navier--Stokes is the work this
invites.

%================================================================================================
\section{Conclusion}
\label{sec:conclusion}

The scatter in a matrix-free operator is usually treated as a synchronisation problem. Treating
it as a data-layout problem instead --- giving every node exactly one owning pack, so that the
owned ranges partition the numbering, and closing the remainder with a gather built by sorting
--- removes atomic additions and colour barriers from the packed application. The local phase
completes before the ghost reduction; stored index arrays fix each node's summation order.
With one thread per pack, the result is bit-identical across the tested thread counts.

Measured on the residual and matrix-free Jacobian action of a colocated CVFEM Navier--Stokes
discretisation on one Grace socket, the format is faster than a standard atomic sweep, than a
coloured one, and than sparse matrix--vector products with the lagged matrix, whose matrix it
replaces with a mesh $\fpMatrixRatioFSixFour\times$ smaller per degree of freedom, with a larger ratio of modelled work to estimated traffic in the historical bare-kernel comparison. The controlled residual diagnostic finds
substantially lower accumulation costs for the packed layout at both one and 72 threads.
These costs account for most of the layout gap within the diagnostic, including the
single-thread case where there is no contention between threads. The margin depends on the
operator: across convective schemes it runs from $\hoFirstLayoutRatio\times$ down to
$\hoDmLayoutRatio\times$ as arithmetic per sub-control surface grows, so a format is worth
reporting against the operator a solver applies rather than the cheapest kernel available.
