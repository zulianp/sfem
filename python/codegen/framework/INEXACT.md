# The Inexact Apply

Partial assembly as a generated kernel: the material tangent is projected onto the constants,
stored once per element, and applied many times without touching the state or the geometry again.

Plan: `plans/inexact_apply.py`. Emitter: `emitters/inexact_apply_codegen.py`.
Op surface: `frontend/ops/sfem_Op.hpp`, generated by `package/op_wrappers.py`.

## Construction

The exact matrix-free apply of a nonlinear-flux operator is

```
(H h)_{i,p} = sum_q  w_q  S_{ikmn}(F(xi_q))  dh_k/dxi_n  dphi_p/dxi_m
```

`S` is the loperand — the material tangent already pulled back through the geometry and
weighted. It varies over the element because `F` does, and that is what forces the quadrature
loop. Project `S` onto P0 (its average over the element) and the loop separates:

```
(H h)_{i,p} ≈ Sbar_{ikmn} · sum_j h_{k,j} Wbar_{jmpn}

Sbar_{ikmn} = (1/|E|) ∫ A_{ijkl} adj_{nj} adj_{ml} / det      per element, from the state
Wbar_{jmpn} = ∫_ref  dphi_j/dxi_m  dphi_p/dxi_n               per element *type*, at codegen time
```

`Wbar` is never computed at run time. The quadrature loop is gone from the apply.

## Naming

`inexact_apply`, never `inexact_hessian`. `apply` is the framework's name for the matrix-free
action of the 2-form; the assembled 2-form is a different thing with its own kernels and formats,
so `hessian` would name a matrix and say the opposite of what the kernel does. Variants are named
after the kernel they vary, not after the mathematics.

## Where the inexactness is

On an affine simplex `F` is constant over the element, so `S` is constant, so its P0 projection is
`S` itself and **the kernel is exact**. `EXACT_ON_ELEMENTS = (TRI3, TET4)`.

The approximation appears only where the state genuinely varies across the cell. That split is the
gate: on an affine simplex the projected apply must reproduce the exact apply to round-off, and any
difference there is a defect, not an approximation.

## The three kernels

One header per element, `<material>_<element>_inexact_apply_inline.hpp`, with `extern "C"`
wrappers in `..._inexact_apply_operator.cpp`.

| Kernel | Reads | Template | Called |
|---|---|---|---|
| `..._inexact_apply_tangent_affine_mesh_soa` | state · geometry · material parameters → writes `Sbar` | `<scalar_t, jacobian_t, tangent_t>` | once per tangent |
| `..._inexact_apply_stored_affine_mesh_soa` | `Sbar` · `h` → `out` | `<scalar_t, tangent_t>` | once per apply |
| `..._inexact_apply_compressed_affine_mesh_soa` | `Sbar` · per-element scale · `h` → `out` | `<scalar_t, tangent_t, scale_t>` | once per apply |

**The apply kernels take no geometry, no state and no material parameters.** The material has been
evaluated away into `Sbar`, and what remains is a contraction identical for every material. This is
the property the split exists for; a change that reintroduces any of the three has undone it, and
`test_the_apply_still_takes_no_geometry_or_state` fails.

Only the affine SoA variant exists. There is no packed, isoparametric or AoS case to choose between.

**The fused variant is not emitted.** It rebuilt `Sbar` on every apply, which is strictly more work
than the exact apply it was compared against. It was scaffolding; the stored apply gates correctness now.

## The store

| | Type | Notes |
|---|---|---|
| tangent | `metric_tensor_t` (`float`) | what SFEM's hand-written partial assembly already stores |
| compressed tangent | `compressed_t` (`half_t`) | plus one `scaling_t` (`float`) per element |

Size per element is `d²` squared, halved when the tangent carries the major symmetry:

| | symmetric (energy) | unsymmetric (residual) |
|---|---|---|
| 2D | 10 | 16 |
| 3D | **45** | 81 |

45 numbers per element in three dimensions **whatever the element**, so the store is small and its
precision is a free parameter — hence the templated `tangent_t`.

Addressed as `element * tangent_element_stride + slot * tangent_component_stride`. Two strides, so
both layouts are reachable without a second kernel: element-major is `(components, 1)`,
component-major is `(1, nelements)`. The generated Op passes component-major.

**The compressed apply scales the outputs, not the tangent.** The action is linear in `Sbar`, so it
is the same number either way, and there are `dim * n_nodes` outputs against the tangent's 45
components — fewer multiplies, and no decompressed copy in registers.

## Rules the construction rests on

**Symmetry defaults to false.** `symmetric=True` is asserted only when the flux's tangent difference
expands to exactly zero. Storing 81 numbers for a symmetric tangent wastes memory; storing 45 for an
unsymmetric one silently averages away its antisymmetric part and returns a *different operator*.
An energy's flux is a gradient, so its tangent is a Hessian and symmetric by equality of mixed
partials. A residual's is a Jacobian and generally is not — Kelvin–Voigt viscosity genuinely is not.

**The symmetry is `S[i,k,m,n] == S[k,i,n,m]`.** The pair that swaps is `(i,n)` against `(k,m)`:
`i` is the output component and `n` the test function's reference direction, `k` the increment's
component and `m` its reference direction. `(i,k)` against `(m,n)` is the plausible-looking wrong
answer, and **no test comparing the staged form against the dense form can catch it**, because both
would share it. It is caught only by evaluating the action against a directly integrated one on a
concrete element.

**`Wbar` is folded, not tabulated.** Storing its values in a runtime table compresses the memory and
destroys the arithmetic: the constants stop being constants, every multiply by zero survives into the
emitted code, and nothing downstream can fold them.

Measured on the same contraction, folded against tabulated: **TET4 is about 4× fewer operations,
HEX8 about 1.4×**, and the tabulated form buys fewer temporaries in exchange. `test_folding_the_constants_beats_tabulating_them`
pins the TET4 case at better than 3×; the exact counts move with
the counting convention, the ratio does not.

Its compression is real and is spent at generation time, where a rational appearing ninety-six times
costs nothing to repeat and a zero costs nothing at all.

**`Wbar` is rank-deficient, and the rank is where the compression lives.** It is the Gram matrix of
the element's gradient functions, so its rank is the dimension of their span — a much stronger
statement than "many entries are zero". A linear simplex is rank one, which is precisely the
loperand; this is the same structure carried to elements whose gradients are not constant.

```
TRI3    6×6  rank 1     TET4  12×12 rank 1     QUAD4  8×8  rank 3
HEX8   24×24 rank 7     TET10 30×30 rank 4
```

**The contraction ordering follows the element, decided by counting.** Two orderings compute the same
action; which wins depends on how much the factorisation actually compresses.

| element | rank / order | staged (`C^T X C`) | gradient-first | chosen |
|---|---|---|---|---|
| TRI3 | 1 / 6 | 52 | 72 | staged |
| TET4 | 1 / 12 | 207 | 342 | staged |
| QUAD4 | 3 / 8 | 238 | 186 | **gradient-first** |
| TET10 | 4 / 30 | 1380 | 1605 | staged |
| HEX8 | 7 / 24 | 2610 | 1731 | **gradient-first** |

`contraction_ordering()` measures both with `sp.cse` and returns the cheaper; emission spells the
answer. Where the rank is high the compression and expansion stages cost more than they save.

**The staged form must survive into the emitted code as stages.** Four named intermediates, each
reading the previous by name. Expanding them into one expression per output and letting CSE
re-discover the structure gives the dense count back, so the stages are the point, not an
implementation detail.

**The previous state is data, not a variable.** A rate-dependent material's previous state enters
through its own physical gradient and is substituted, never differentiated against: the tangent is
the derivative with respect to the current state alone. Both are absorbed into `Sbar`, which is why
the apply never sees either.

**Gather only what is read.** `state_dependence()` returns the state values the projected tangent
actually reads. A state-independent material — linear elasticity, whose tangent is the constant
elasticity tensor — reads none, and a kernel that gathers a state it never uses carries twelve dead
loads on a tetrahedron and twenty-four on a hexahedron.

## Layering

Everything above is decided in `plans/inexact_apply.py`. The emitter prints it.

- **Applicability** is `emittable_inexact_apply_plan()`: an element with no symbolic basis, a plan
  disagreeing with the specialization, a rule whose reference gradients are not an affine simplex's
  constants, or a form whose field arity is not the spatial dimension. Emission asks once and looks
  the answer up through a table — `_KERNEL_BY_APPLICABILITY`, `_PREVIOUS_STREAMS_BY_USE` — never a branch.
- **The projection** is `projected_tangent()`, and it lives in the plan because two kernels once
  needed the same answer. Emitting it from two places is how they drift apart.
- **The parallel pragma and the scatter-add** come from the bound target, never from a literal.

## The Op contract

```cpp
virtual bool inexact_supported() const;                     // default false
virtual int  inexact_update(const real_t *const x);         // assemble Sbar at x
virtual int  inexact_apply(const real_t *const h, real_t *const out);
```

- **`apply` continues to mean the exact operator.** The inexact path is reached only through
  `inexact_update`, so no existing caller changes behaviour when an operator gains support.
- **`inexact_update` is explicit and never implicit.** The store stays valid until the next call.
  A Newton step assembles once and applies for every Krylov iteration — that is the whole reason the
  split pays — so the caller says when it is rebuilt rather than having the operator guess. Nothing
  invalidates it silently; an operator whose state has moved without a call returns a tangent for the
  old state.
- **`inexact_apply` takes no state.** The state was consumed by `inexact_update` and lives in the
  store. The signature says so.
- **A missing precondition is fatal, not probed.** Applying before updating is a programming error:
  the generated Ops `SFEM_ERROR` out, as they already do for a missing geometry cache.
- **`inexact_supported()` asks the geometry cache, not what was generated.** The tangent is assembled
  from the cached affine adjugate and determinant, and smesh's adjugate fill has no TRI3 or QUAD4
  case — it aborts. Reporting support the operator cannot deliver is worse than reporting none.
  For the same reason `initialize` forces the affine cache for the split in three dimensions only.
- The store is `SharedBuffer<metric_tensor_t>` beside the geometry cache, sized on first use and
  refilled in place: a Newton solve calls `inexact_update` once per step for the life of the
  operator, and reallocating each time would dominate a kernel whose purpose is to be cheap.

The compressed entry point is on the C ABI but the generated Op wires only `stored`.

## Opt-in

Off by default. `inexact_apply=True` on the material, or `--inexact-apply` / `--no-inexact-apply`
as a tri-state on the generator, like the matrix-format options. A material that does not ask
generates nothing and overrides nothing, so `Op`'s refusing defaults stand.

## Gates

| Claim | Gate |
|---|---|
| the reference tensor is integrated correctly | symbolic integration vs. quadrature; major symmetry; entries are rationals |
| its shape is what the folding decision rests on | recorded `(entries, distinct, zeros)` per element — a change in them is a change in that case |
| the factorisation is exact | `C^T X C - Wbar == 0`, checked at construction, not trusted |
| both orderings agree, and the cheaper is chosen | asserted per element, with the costs recorded |
| symmetry is not silently assumed | a symmetric tangent gives the same action either way; indices are distinct without it |
| **the projection is exact where it must be** | the projected action equals a directly integrated one on a concrete tetrahedron, and the affine-simplex action matches one-point quadrature |
| the split is reachable from SFEM | each kernel crosses the ABI at both precisions; the store uses SFEM's own types |
| the apply has not regained what it exists to shed | no geometry, no state, no material parameters in the ABI body |

Correctness of the emitted kernels is carried by `tools/reproducibility.py`, not by byte-identity:
this path changes generated output by construction. Report throughput with the dof count, the thread
count and the machine, and quote break-even in applies per assembly.
