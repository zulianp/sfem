Analysis & design · python/codegen/framework

SFEM Codegen Layering

The framework documents a four-stage lowering pipeline and ships a rich plan vocabulary. The code runs a two-stage pipeline in which two very large emitters do the planning, and the plans mostly watch.

Scope 62,930 LOC Python across 12 packages Out of scope the mlir/ subtree Prescriptive docs PIPELINE · REFACTORING · REFACTORING_2 · PRD · KERNELS Date 2026-09-02

This document does two things. First it establishes, with citations, where the implementation departs from the architecture the framework's own documents prescribe — not as a style complaint, but by tracing which module actually decides each thing. Then it proposes an eight-layer target architecture, drawn as a stack, with an explicit contract at every boundary and a migration order in which each step is separately shippable behind a byte-identity gate.

Diagnosis

There is no kernel-level semantic model. Between FormCollection (symbolic, complete) and generated C++ text (concrete, complete) the framework has nothing that decides: no object that says which loops exist, which values are hoisted to which scope, which buffers are gathered, which scatter is used. Those decisions live inside emitters/residual_codegen.py and emitters/energy_codegen.py as control flow interleaved with string construction.

The plans/ package is what that missing model should be. It is written, documented and unit-tested — and almost none of it reaches an emitter. The plan objects are handed to the emitters as optional keyword arguments and used to validate names the emitter already chose.

Everything else — the import cycles, the target hardcoded inside an emitter, the backend that fabricates a symbolic system to satisfy an emitter's signature, the six unused assembly plans — follows from that one gap. A layer that produces no artifact cannot be depended on, so the layers below it reach around it and take what they need from wherever it actually exists.

PART 1

What the code is actually shaped like

The README.md in the package states the intended order plainly: “This package is organized by lowering layer.” The order it lists is symbolic → fem → plans → ir → emitters → backends. Read as a lowering pipeline, imports should point upward, toward the specification: a later stage names the types of the artifact it receives, and an earlier stage never names a later one.

Of the 17 directed package pairs that exist in the import graph, 11 point the right way and 6 point the wrong way — including all four of symbolic's outgoing edges.

Findings

Each finding names the mechanism, not the symptom. Evidence is given as path:line against the working tree.

F1
The emitters take symbolic objects; the plans arrive sideways as validators structural

The main residual entry point is generate_coupled_residual_sfem_files(system, *, prefix, emission_plan, …, reference_data_plan=None, diagnostics_plan=None, matrix_format_plan=None). The required first argument is a CoupledResidualSystem — a symbolic object from stage 2. Every plan is optional, and where one is supplied the emitter calls validate_reference_data_plan(...) and validate_diagnostics_plan_names(...) against names it has already computed itself. The energy entry point has the same shape with forms in place of system.

This inverts the intended relationship. The plan should be the emitter's only input; instead the emitter re-derives the plan internally and the plan checks its homework.

emitters/residual_codegen.py:1739–1800 · emitters/energy_codegen.py:560–590
F2
Most of the plan vocabulary has no consumer dead layer

LocalPhasePlan, MeshPhasePlan, DataStreamPlan, BlockPlan, LocalKernelPlan, MeshKernelPlan and GeometryPlan are referenced only inside plans/ itself (plus fem/geometry.py for the last). No emitter reads them. The six matrix-assembly plans are worse: CRSAssemblyPlan, BSRAssemblyPlan, DIAAssemblyPlan, COOAssemblyPlan, PatchAssemblyPlan and BlockDiagSymAssemblyPlan appear in exactly three places — their definition, the flat re-export in __init__.py, and tests/test_m11_matrix_formats.py.

Meanwhile the actual CRS scatter is built from string literals inside the energy emitter, and format selection is a substring test on a tuple of names: if "crs" in formats:. The plan describes row pointers, column indices and accumulation policy; the emitter ignores it and hand-writes the loop.

F3
symbolic/core.py is a vertical slice of the whole pipeline structural

One 2,556-line file named for the bottom layer contains, in order: a C99CodePrinter subclass and _sfem_ccode; SFEM math-header source strings; the symbolic objects proper (DeformationGradient, FirstPiolaStress, …); the SoA weak-form builders; and then the entire scheduling engine — ExpressionGraph, ExpressionCost, EvaluationPlan, LivenessState, EvaluationMetrics, scope hoisting, pattern detection, register-pressure estimation — followed by generate_cpp_kernel, generate_openmp_cpp_kernel and generate_cuda_kernel.

F4
FormCollection.source is a back-pointer to the stage that was supposed to end leak

PIPELINE.md declares FormCollection the standardized handoff: “once an equation has been lowered, downstream stages use only the resulting FormCollection.” It then blesses the escape hatch two paragraphs later — “FormCollection.source for the lowered CoupledResidualSystem” — and downstream duly uses it, in the planning layer, the backend layer and the emitters.

The consequence is visible at backends/openmp.py:776: to emit a diagonal block, the backend constructs a fresh CoupledResidualSystem, copies parameters off collection.source, adds one field per component and registers sp.S.Zero residuals — a synthetic symbolic system fabricated purely to satisfy the emitter's argument type. A backend is doing symbolic algebra because the emitter's interface has the wrong shape.

F5
The IR exists and is bypassed dead layer

ir/kernel_ast.py is a well-formed 573-line kernel IR: typed loops with vectorization and tabulation strategies, buffer declarations, gather and scatter nodes, geometry nodes, a partial-assembly strategy enum, plus KernelASTPass and KernelASTPassPipeline for transformations. The energy path uses it for four fragments (the outer loop and scatter shapes). The residual path — 10,102 lines, the main production path — never constructs a node. KernelASTPass and KernelASTPassPipeline are referenced only from tests/test_gen_api.py.

The whole transformation vocabulary the PRD asks for — vectorization, unrolling, packing, per-warp variants — has a home and no tenant.

F6
Provenance survives all the way to the backend structural

PIPELINE.md's stated core requirement is that “energy and residual models are not two separate code-generation pipelines … after that, the code-generation stage is one shared process.” In practice OpenMPSoABackend._traversal branches on unit.kind into energy_soa, residual_soa and boundary_residual_soa, and each branch reaches a different emitter module of 8,470, 10,102 and 1,214 lines. CUDASoABackend supports only energy_soa and raises on anything else.

Those three modules independently re-implement the same concerns. Counting identifier occurrences: adjugate geometry appears 87 / 161 / 0 times, scatter 56 / 51 / 22, packed layout 92 / 114 / 0, tensor-product handling 227 / 115 / 9. This is not shared code with three entry points; it is three parallel code generators.

F7
The target is a constant inside the emitter structural

emitters/residual_codegen.py:57 reads, in full: def _target(): return OpenMPTarget(). Every pragma, inline qualifier, atomic form and work-item index in the residual path resolves through it. emitters/boundary_codegen.py does the same. The target layer that PRD M5 specifies therefore has no purchase on the residual path at all — a CUDA residual kernel is not a configuration change, it is a fork.

The energy path does better and shows what the seam should look like: OpenMPEnergySoASourceBuilder and CUDAEnergySoASourceBuilder inject header naming, inline qualifiers, preamble lines and geometry headers into one shared emitter. That strategy object is the right idea applied at one seam; it should be the whole target layer.

emitters/residual_codegen.py:57, 147–178 · working counter-example: emitters/energy.py:151–408
F8
The orchestrator and the packaging layer live outside the framework leak

UserInputStage, SpecializedFormManipulationStage, CodeGenerationStage, CodeGenerationUnit and generate(...) — the four stages PIPELINE.md is about — are defined in python/sfem/gen.py, 2,287 lines in the runtime package. The C ABI, sfem::Op wrapper and factory generation that PRD M6 assigns to the framework live in python/sfem/_gen_op.py, 7,388 lines. Every material in the framework's own materials/ package therefore opens with from sfem import gen — the framework reaching into the runtime package to find its own pipeline.

Compounding this, codegen/framework/__init__.py re-exports 262 names in one flat namespace, so sfem/gen.py imports ~120 symbols from every layer at once. There is no import through which a layering rule could be stated, let alone enforced.

F9
The safety net is 449 assertions on generated C text test shape

F10
Generated output depends on the name of the output directory leak

Found while building the S0 gate, not by reading. _uses_generated_shared_primitive_headers(out_dir, material_name) decides whether the five shared primitive headers — kernel_math.hpp, geometry_kernels.hpp, tensor_product_kernels.hpp, kernel_diagnostics.hpp, packed_thread_scratch.hpp — are hoisted into one copy at the tree root or duplicated per material. It decides by taking os.path.basename of the output directory's parent and testing it against the literal string "generated".

Generating into <anything>/generated/laplace emits 520 files with #include "../../kernel_math.hpp"; generating into <anything>/reference/laplace emits 559 files with #include "../kernel_math.hpp". Same inputs, same code, different output — selected by a path string that no plan mentions and no caller passes deliberately.

This is packaging policy (L7) implemented as a string test inside the generation driver. It is also a live hazard for the migration: a gate that regenerates into a scratch directory silently compares the wrong tree, which is exactly what happened on the first attempt.

python/sfem/gen.py:1697–1704
F11
What the byte-identity gate cannot see gate design

Two blind spots showed up while running S2 and S3, both worth stating because the migration leans on these gates.

A test module that stops loading is invisible to it. After the weak-form relocation, tests/test_neohookean_ogden.py failed to import — unittest reported one _FailedTest, seventeen real tests silently stopped running, and both the snapshot check and the targeted unit tests stayed green. The cause was symbolic/__init__.py re-exporting one module's namespace rather than the package's, so any relocation inside the layer removed names from the package surface. The gate reported nothing because it never ran. The script now captures that status, runs everything, and exits with it at the end.

PART 2

The target stack

Eight layers. The count is not arbitrary: each boundary is placed where a distinct kind of decision is finished, and the test of a boundary is that a concept can be named above it and is unnameable below it. Provenance (energy or residual) ends at L1. Element identity ends at L2. SymPy ends at L3. Loop structure is fixed at L4. Target ends at L5. Text begins at L6.

The two shaded layers, L3 and L4, are the ones the framework is missing. Everything else is present today and mostly needs relocating rather than rewriting.

Layer contracts

A layer boundary is real only if it is stated as a rule that can fail a test. Each layer below gives its input, its output, and the thing it is forbidden to name.

L0
Specification

The user-facing mathematical API: UFL-conforming fields, operators, qualifiers, and the EquationSystem / EquationSystems container. Pure SymPy, importable on its own.

in user codeout EquationSystem
May not name any other framework layer, any element type, any target, any layout, or any string of generated code. This single rule deletes all four of today's outgoing symbolic/ edges.
L1
Form lowering

Turns either user notation into the standardized 0/1/2-form collection: differentiation for energy input, direct assembly for residual input, dependency pruning, and the row/column block structure for coupled systems. This is where weak_residual_coefficients and coupled_residual_weak_coefficients belong — today they live in the residual emitter and are imported back up by symbolic/equations.py:19.

in EquationSystemout FormCollection
May not name elements, quadrature, geometry, targets — and may not leave a .source back-pointer. Anything a downstream layer needs from CoupledResidualSystem becomes a field on FormCollection or FormBlock. This is the boundary at which provenance dies.
L2
Discretization

Element families, basis and quadrature data, affine vs. isoparametric geometry policy, tensor-product and sum-factorization policy, mixed-order compatibility (Taylor–Hood pairs). Produces a DiscretePlan: the element contexts, basis plans, geometry plans and reference data for one generation request. Largely the existing fem/ package plus plans/emission.py and plans/reference_data.py.

in FormCollection + element requestout DiscretePlan
May not name a target or emit text — which removes fem/tensor_product_geometry.py:1's import of OpenMPTarget and moves its line-building into L6.
L3
Kernel planning new load-bearing layer

The layer the framework is missing. It decides everything about the kernel that is not syntax: the expression graph and common-subexpression structure, which values hoist to which scope (mesh, element, quadrature, test, trial), liveness and register-pressure estimates, arithmetic intensity, the data streams and their layouts, the mesh and local phase sequences, the block decomposition, and which matrix-format variants are requested.

Most of this code already exists — ExpressionGraph, EvaluationPlan, ExpressionCost, LivenessState in symbolic/core.py:1123–1445, and the whole plans/ vocabulary. It needs to be assembled into one layer whose output is a KernelPlan complete enough that nothing downstream needs to look further up.

in FormCollection + DiscretePlanout KernelPlan
May not construct or differentiate forms, and may not emit text. It carries SymPy expressions as opaque payload and is the last layer permitted to hold them.
L4
Kernel IR new load-bearing layer

Concrete, typed, target-neutral: loop nests with explicit bounds, buffer declarations, gather and scatter nodes, geometry nodes, calls. ir/kernel_ast.py already defines this and is ready to use. Structural transformations run here as KernelASTPass objects — vectorization, unrolling, blocking, scratchpad packing, one-pass vs. two-pass packed traversal, per-thread and per-warp variants.

This is where the PRD's optimization goals become tractable: a pass is a testable function from AST to AST, and KernelASTPassResult already carries the metadata to say whether a pass was parity-preserving or performance-changing.

in KernelPlanout KernelAST
May not contain C or C++ syntax, or SymPy expressions other than as opaque leaf payload.
L5
Target lowering

One target class per platform, each doing two things: AST-to-AST rewrites (parallel-for shape, work-item indexing, atomic strategy, vector width, memory space, matrix-unit microkernels) and supplying a TargetDialect of syntax facts (inline qualifier, pragma spelling, restrict keyword, header conventions). OpenMPEnergySoASourceBuilder / CUDAEnergySoASourceBuilder are the working prototype of the second half; generalize them and delete _target().

in KernelAST + Targetout lowered KernelAST + TargetDialect
May not know which physics produced the kernel, and may not build source lines beyond dialect tokens.
L6
Emission

Mechanical. One printer walks a lowered KernelAST against a TargetDialect and produces text; a second small component assembles files and names. If the printer contains a branch on physics, provenance, element family or matrix format, a decision has leaked down from L2–L5.

Realistically this is a few hundred lines. The 19,786 lines in today's three emitters are almost entirely L3 and L5 material wearing a printer's name.

in lowered KernelAST + TargetDialectout source files
May not import L0–L3. The import test is the enforcement.
L7
Packaging

Everything about delivering the generated set rather than generating it: hoisting shared primitives into common headers so kernels include rather than re-generate them (KERNELS.md's “Cleaner Generated Code”), the C ABI, the sfem::Op subclass, factory registration, the HEX8-wraps-PROTEUS_HEX8 aliasing, and the FLOP/arithmetic-intensity reports built from L3 cost data. Today this is sfem/_gen_op.py plus the alias machinery at sfem/gen.py:1311–1531, both outside the framework.

in source files + KernelPlan metadataout build-ready artifact set
May not change kernel bodies. If packaging needs a different kernel, that is an L3 request, not a post-edit.

The three rules that make the boundaries real

One direction. Imports point up only. Enforced by a tests/test_layering.py that walks the AST of every module, maps it to a layer, and fails on any downward edge. This is roughly thirty lines and would fail today on six package pairs — which is exactly why it is worth having before any relocation starts.

Closed handoffs. No back-pointers, no getattr(x, "source", None), no plan carrying unit and context so the consumer can reach back through it — which EnergySoAKernelEmissionPlan does today.

The original wording of this rule asked every boundary artifact to survive a JSON round trip. That is wrong above L3, and S4 is where it broke: FormCollection carries SymPy expressions by design, and L3 is defined as the last layer permitted to hold them, so a JSON round trip is not available at the L1 boundary and never was. The rule splits in two. Above L3 the testable property is severability: cut the back-pointer, re-run the layers below, and get an identical result — which is exactly what tests/test_form_collection_boundary.py does. From L3 downward, where SymPy has ended, the JSON round trip applies as originally written.

One dispatch axis per layer. A layer may branch on the concept it owns and on nothing a layer above owns. No if kind == "energy_soa" in a backend; no if "crs" in formats in a printer; no if material.name != "linear_elasticity" anywhere.

PART 3

One path, before and after

Abstractly the target stack is uncontroversial. It is worth seeing what it changes for a single concrete path — the two-phase-flow residual on HEX8 — because that is where the cost lands.

PART 4

Migration

The order below is chosen so each step is independently shippable and reversible, and so the riskiest step (S5) comes only after the safety net exists and the interfaces have already been narrowed.

The gate for S0–S6 is byte-identical generated output across the full generator set. That is a stronger gate than a test suite and it settles the performance question by construction: if the emitted C++ is unchanged, kernel performance is unchanged. Only S7 intentionally changes output, and it carries a benchmark gate instead — throughput unchanged within measurement noise, measured before and after, not inferred.

S0
Snapshot the output done

tools/codegen_snapshot.py regenerates all 11 maintained materials through their real entry points and compares the result byte for byte. capture writes a 44 MB reference tree plus a committed hash manifest; check diffs against the tree and shows what moved; verify compares hashes only, so CI and a fresh clone need no reference tree. Baseline: 520 files, and both modes confirm the tree reproduces exactly.

Two things worth knowing came out of building it. Generation is deterministic across processes — no hash-order or timestamp instability, and no absolute paths embedded in the output, so a reference tree is portable between checkouts. And the gate must generate into a directory named generated or it silently compares a different tree (F10).

gate — none; this step creates the gate
S1
Add the layering test, with the six known edges allowlisted done

tests/test_layering.py parses every module with ast — it never imports them, so import side effects can neither hide a violation nor break the test — and maps each to its layer. It finds 17 layer-to-layer edges: 11 upward, 6 downward, matching the analysis exactly. The six are pinned in KNOWN_VIOLATIONS.

The ratchet cuts both ways, and both directions are negative-tested: a newly introduced downward import fails test_no_new_downward_imports, and a violation that gets fixed but is left in the allowlist fails test_known_violations_are_still_present. So the list can only shrink, and it cannot go stale.

gate byte-identical output (trivially — no source changes) · added to run_m9_regression.sh
S2
Cut the four symbolic/ edges done

All four are gone; the allowlist is down from six entries to two. Four moves did it: the weak-coefficient builders (WeakResidualCoefficients, weak_residual_coefficients, coupled_residual_weak_coefficients) out of the 10k-line residual emitter into symbolic/residual.py, where they always belonged — they are sp.diff plus a linearity check, with no emission in them; sfem_soa_adjugate_geometry_inputs into fem/reference.py, which also deletes a lazy import symbolic inside fem that existed only to reach back for it; and the three generate_*_kernel entry points with their nine private helpers into a new emitters/kernel_codegen.py, which is what freed core.py of OpenMPTarget and CUDATarget.

The fourth was not a move at all. symbolic/core.py imported eighteen names it never used — from fem.reference, fem.tensor_product_geometry, emitters.quadrature_codegen and plans.reference_data. They were not dead: emitters/energy_codegen.py imported them through symbolic.core, which re-exports its own namespace. So the specification layer was acting as a pass-through for element, quadrature and plan symbols on behalf of an emitter, and that laundering was the entire reason three of the four edges existed. Pointing those imports at their real homes removed them.

symbolic/core.py is now 2,149 lines, down from 2,556.

gate byte-identical output (520 files) at each of the four moves · full suite unchanged · ratchet 6 edges → 2
S3
Split symbolic/core.py along its seams done

The printer seam. The C99CodePrinter subclass, _sfem_ccode, the specialized-pow helpers, the math-header sources and the C naming helpers are now emitters/cprinter.py. Once S2 had moved the three generate_*_kernel entry points out, this cluster was fully isolated — nothing referenced it in either direction.

The artifact and weak-form seams. GeneratedKernelCode and GeneratedKernelFile are emission outputs, so they moved to emitters/artifacts.py. The SoA weak-form builders moved to symbolic/weak_forms.py — L1 living inside the symbolic/ package until L0 and L1 get separate packages.

The scheduling seam. 33 symbols — ExpressionGraph, EvaluationPlan, ExpressionCost, LivenessState, EvaluationMetrics, CSE, scope hoisting, pattern detection, cost and liveness estimation — are now plans/scheduling.py. L3 exists.

The single back-edge was resolved by deleting it rather than hiding it. KernelExpressions.build_graph is gone; the class exposes .expressions instead, and build_expression_graph accepts either that builder or a plain iterable. The three convenience wrappers that lived on the symbolic systems (build_residual_graph, build_jacobian_action_graph, and the two-phase equivalent) are now free functions in the planning layer that take a system and ask it for its expressions. 48 call sites were rewritten through the AST rather than by pattern matching, because the receivers include multi-line method chains.

Result: symbolic/ has no outgoing edges at all. It is now a true bottom layer — importable, testable and reusable without dragging in element policy, target policy or an emitter. symbolic/core.py is 1,245 lines, down from 2,556.

gate byte-identical output (520 files) at every seam · 193 tests, failure set unchanged from S2
S4
Close FormCollection done

The collection now carries what downstream needs as first-class data: residual_fields (the lowered field records with their value, gradient, test, previous and direction symbols), residual_expressions, jacobian_action_blocks and parameters. The last three cannot be inferred from the 1- and 2-form blocks — for mixed formulations those are keyed by assembled field name (u) while the lowered fields are per component (u0, u1), which is what made poro-hyperelasticity fail the first attempt.

FormCollection.source no longer exists. The planning layer's reach-throughs went first, then the emission path's, then the field itself.

gate byte-identical output (520 files) · enforced by tests/test_form_collection_boundary.py
S5
Invert the emitter interface severed; decisions still to move

The step everything else was preparing for, and it turned out to be far smaller than feared — because the dependency was measured rather than assumed. Across 10,102 lines the residual emitter reads exactly eight members off the CoupledResidualSystem it was handed, and every one is a function of data the lowered collection already carries. The boundary emitter reads one.

plans/residual_model.py is that surface and nothing more. ResidualEmissionModel is built from a closed FormCollection, so the emitter's input is now derived from the artifact rather than from the stage that produced it. Before rewiring anything, the model was checked against the system it replaces across every residual material — fields, dimension, parameters, both dependency sets, the Jacobian blocks expression by expression, the action data symbols, and the role-tagged kernel expressions in both include_blocks modes — and matched exactly.

The synthetic CoupledResidualSystem that backends/openmp.py fabricated for diagonal blocks moved into the planning layer as diagonal_block_emission_model. It still uses the symbolic system as the builder that knows how to mint a lowered field's symbols, but nothing of it escapes: the return value is a model. A backend is no longer doing symbolic algebra.

What remains. This severs the emitter from the symbolic layer; it does not yet move the emitter's decisions — loop structure, scopes, streams, layouts — up into L3. The model deliberately mirrors the system's method names so that ten thousand lines of emitter did not have to change at the same time. Migrating those decisions is the rest of S5 and is what S6 needs before the IR can carry them.

gate byte-identical output (520 files) · 201 tests, failure set unchanged from S4
S6
Split backends/; route through the IR split done — zero violations

The layer graph is clean. Every import in the framework now points up the lowering order, and KNOWN_VIOLATIONS is empty.

Neither remaining entry was a violation to repair; both were packages holding two unrelated things. backends/ held the target definitions, which belong below planning and above emission, alongside the orchestrators that drive the emitters — so targets/ is now its own layer (L5) and an emitter naming a target is the upward edge it always was. fem/ held two emitter modules: thirteen of the eighteen functions in tensor_product_geometry build C text, and every one of its importers was already in emitters/, so both modules moved there. Discretization no longer emits source.

The final graph is twelve edges, all upward:

symbolic → fem → plans → ir → targets → emitters → backends

Still open: _target(). emitters/residual_codegen.py:74 is still def _target(): return OpenMPTarget(), and the boundary emitter has its twin. This is no longer a layering violation — the emitter may name a target — but it is still a hardcode, and it is what keeps a CUDA residual kernel a fork rather than an argument. Threading a target parameter through would touch 43 functions transitively (31 calling a wrapper directly), all of them emitter internals that the AST migration is meant to collapse into a printer. Doing it now is work the next step undoes, so it is deliberately deferred to the AST migration rather than done twice.

gate byte-identical output (520 files) · 201 tests, failure set unchanged · ratchet 6 edges → 0
S7
Put the assembly plans to work

Drive CRS/BSR/DIA/COO/patch scatter from the plans that already describe them, and hoist shared primitives into common headers per KERNELS.md. This is the one step that intentionally changes generated text, so byte-identity no longer applies.

gate numerical parity + benchmark: assembly and apply throughput unchanged within measurement noise, measured before and after
S8
Bring the driver and packaging inside done

sfem/gen.py — the four pipeline stages and generate(...), 2,287 lines — is now codegen/framework/pipeline/driver.py. sfem/_gen_op.py — the C ABI, sfem::Op wrapper and factory generation, 7,388 lines — is codegen/framework/package/op_wrappers.py. Both keep thin re-export shims at their old paths, so all 36 callers work unchanged.

The move exposed one more instance of the F10 pattern. gen.py derived the repository root as dirname(__file__)/../.., correct only while the module lived in python/sfem/; relocating it would have silently pointed the compiler's include paths at python/codegen. It now walks up looking for a marker instead of counting ...

The 262-name flat facade is documented rather than deleted. Exactly one module imported it — the driver — and its 125 names now resolve to 16 concrete layer modules, so the driver's dependencies are visible per layer instead of hidden behind a namespace that names none. The facade stays for callers outside the framework, and a new test fails if any framework module imports through it: an import that names no layer is one the layering rule cannot be stated at, which is precisely how the flat namespace made the architecture unenforceable.

PART 5

Decisions taken

Four questions I raised; all four are now settled. They are recorded here because each one constrains code that has not been written yet — the column on the right is the rule a reviewer should hold the implementation to.

QuestionThe trade-offDecision
Does CSE belong to L3 or L4? CSE on the SymPy graph (L3) sees algebraic structure and can exploit it; CSE on the AST (L4) sees the real loop nest and can hoist across scopes correctly. Today it is L3-shaped, inside symbolic/core.py. L3. CSE runs on the SymPy graph, in kernel planning. L4 receives an expression set that is already factored and is responsible for placing it, not for rediscovering it.
Packed and patch mesh layouts: L2 or L3? They are traversal and data-layout choices, not discretization — but they interact with element connectivity, which is L2's. L3. Kernel planning owns the layout: L2 supplies connectivity and element facts, and every traversal variant — standard, packed one-pass and two-pass, patch — is planned in L3 as a different KernelPlan over the same discretization.
How much of L3 should be one plan versus a plan per form family? One KernelPlan type keeps L4 simple; per-family plans keep each simpler but reintroduce the dispatch that F6 is about. One type, varying by data. A single KernelPlan whose contents differ per form family — no subclass, no family enum that L4 or L5 branches on. If a consumer has to ask which family produced a plan, the plan is missing a field.
Is S5 one branch or a long-lived parallel path? A parallel implementation behind a flag is safer but doubles the surface for months. A per-family in-place inversion keeps one code path but has larger individual commits. In place. No parallel implementation and no feature flag; the inversion happens on the existing code path, one form family at a time, with byte-identical generated output as the gate on every commit.
