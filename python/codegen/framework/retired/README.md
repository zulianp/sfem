# Retired documents

**Nothing here is maintained, and nothing in code may cite it.** These are kept because they
record why decisions were taken, not what is true now. Where a retired document and the current
code disagree, the code is right and the document is not being fixed.

Current documentation is one directory up: `README.md` (layout), `PRESCRIBED_ARCHITECTURE.md`
(the rules), `ARCHITECTURE.html` (where it stands), `INEXACT.md` (the projected apply), and
`docs/` (worked examples).

## The test that retired them

Each of these was written before the framework was split into lowering-layer packages, and
**none of them names a single one of the nine** (`symbolic fem plans ir targets emitters
backends package pipeline`). They describe a flat module layout that no longer exists. The two
current architecture documents name all nine.

## Specific things these documents get wrong

Named so nobody re-derives them from here:

- **`KERNELS.md`** lists 26 plan types. Ten no longer exist — `AssemblyDiagnosticsPlan`,
  `COOAssemblyPlan`, `DIAAssemblyPlan`, `ElementAssemblyKernelPlan`, `ElementDofPlan`,
  `ElementLocalMatrixPlan`, `ElementLoopPlan`, `ElementTemporaryPlan`, `PackedAssemblyPlan`,
  `PatchAssemblyPlan` — and it names none of the ~45 added since.
- **`M11.md`** deliverables D7 (DIA), D8 (COO) and D9 (Patch) specify formats that were
  generated, shipped, and then removed to reduce scope during the rework. `MatrixFormat` is
  CRS, BSR and BlockDiagSym today, so D7-D9 describe code that is in history rather than in the
  tree -- which is a reason to read them if those formats come back, not a reason to trust them.
- **`PRD.md`** goal 8 asks for DIA, COO and patch assembly. That goal still stands; the three
  formats were removed to reduce scope during the rework, not decided against, and the code is
  recoverable from history. This is the one part of `PRD.md` that has not been superseded.
- **`PIPELINE.md`** describes three reference materials, one of which (poro-hyperelasticity) is
  no longer generated by default, and a shared code-generation stage that the residual path does
  not actually have — see `tests/test_residual_path_capabilities.py`.
