# M11. Matrix Formats and Assembly Backends

Source milestone: [PRD.md](PRD.md)

Kernel-plan reference: [KERNELS.md](KERNELS.md)

## Objective

Make matrix-format generation a first-class codegen path for assembled
operators and format-aware matrix-free operators. The milestone starts from the
same symbolic forms, `FormCollection`, `GenerationPlan`, `KernelPlan`, and
backend traversal used by energy, residual, and Jacobian-action kernels.

The generated code must stay procedural, SoA-first, branch-light in hot loops,
and friendly to compiler vectorization on AVX512-class CPUs. Planning and
diagnostic metadata may use Python structures, but emitted kernel hot paths
should avoid STL containers and indirect control flow that inhibits
vectorization.

## Current Baseline

The initial M11 scope is implemented as planning and diagnostics:

- `MatrixFormatPlan` and `MatrixAssemblyVariantPlan` describe CRS, BSR, DIA,
  COO, patch, and block-diagonal symmetric variants.
- Standard and packed mesh layouts are represented, including packed one-pass
  and two-pass variants.
- Patch node-index filtering and format-aware apply markers are plan metadata.
- Matrix format plans specialize from the same field, basis, and block context
  used by matrix-free kernels.
- Generated `matrix_formats.hpp` and
  `<operator>_matrix_format_operator.cpp` expose FLOP, byte, and arithmetic
  intensity diagnostics.
- `sfem.gen.generate(...)`, `sfem.gen.run(...)`, and `CodeGenerator` accept
  matrix-format requests without changes to symbolic material definitions.
- Regression coverage exists in
  `python.codegen.framework.tests.test_m11_matrix_formats`.

## Implementation Sequence

1. Freeze the request grammar and plan serialization.
2. Complete plan-specialization coverage for scalar, vector, mixed monolithic,
   and mixed block operators.
3. Keep diagnostics emission compiling cleanly for every requested variant.
4. Implement CRS assembly first because it is the most general reference path.
5. Implement COO triplet emission as the simplest independent cross-check.
6. Implement BSR for vector and mixed blocks once CRS reference coverage is
   stable.
7. Implement DIA only for cases where planning proves compact diagonal
   structure.
8. Implement patch assembly and indexed patch assembly.
9. Bind standard and packed mesh layouts to real SFEM data structures.
10. Add wrapper/factory runtime format selection.
11. Add generated numerical equivalence tests against existing SFEM assembly.
12. Add performance benchmarks and use diagnostics metadata in the reports.

## Acceptance Criteria

- Maintained materials can request CRS, BSR, DIA, COO, patch, and
  block-diagonal symmetric variants from the same form and plan data.
- Standard and packed layouts are explicit in generated plans and emitted code.
- Packed variants report one-pass or two-pass behavior with expected memory
  traffic and arithmetic intensity.
- Matrix-format metadata sources compile from a clean output directory.
- Real assembly kernels, once added, match existing SFEM assembly references.
- Format-aware matrix-free apply kernels match matrix-free reference output.
- Generated hot loops remain procedural, SoA-first, branch-light, and free of
  STL containers.
- Symbolic material definitions do not contain matrix-format policy.
