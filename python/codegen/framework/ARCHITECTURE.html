SFEM Codegen Architecture

The layer graph is clean and enforced, and the matrix-free apply path is now measured as well as described. The emission layer still holds 23,498 lines that should be a printer — up from 22,727, because node construction is longer than string appends, which is why it is now measured by the decisions it makes rather than by its size.

Package python/codegen/framework Branch codegen-layering, 42 commits from 060684ff Out of scope the mlir/ subtree Date 2026-09-03 (second pass)

This document separates two things that the previous analysis deliberately ran together: what the architecture requires of each layer, and what each layer currently is. They are drawn against the same eight rows so the difference can be pointed at rather than described. Everything after that is the list of decisions still open, with the cost of each and what it blocks.

Where things stand

Structure is done: every import in the framework points up the lowering order, zero violations, enforced by a test that fails on any new one. The specification layer has no outgoing edges at all. The planning layer exists. Nothing architectural lives outside the framework.

Behaviour is not. The emission layer still makes the decisions the planning layer is supposed to make — which loops exist, what hoists to which scope, which buffers are gathered, how a matrix scatters. Thirteen plan types and six assembly plans describe those decisions and no emitter reads any of them.

Put plainly: the boxes are in the right places and the arrows point the right way, but the work is still being done in the wrong box. Every open point in Part 3 is either that problem or a consequence of it.

PART 1 · PRESCRIPTIVE

What each layer must own

Eight layers. Each boundary is placed where a distinct kind of decision is finished, and the test of a boundary is that a concept is nameable above it and unnameable below it. The figure pairs each layer's requirement with what occupies it today, so the two readings share a row.

The rules that make a boundary real

Three, each enforced by a test rather than asserted in prose. They are what stopped the layer graph regressing while 6,000 lines moved between packages.

PART 2 · DESCRIPTIVE

What is actually built

Two facts about the current tree. The first is good and finished; the second is the reason this document exists.

The import graph is clean

Twelve layer-to-layer edges, every one pointing up the lowering order. It started at seventeen edges with six pointing the wrong way, including all four leaving the specification layer.

The decisions are still in the wrong layer

What the clean graph does not show: the emission layer receives plan objects and ignores them, re-deriving the same decisions internally from SymPy and element metadata. The plan layer describes the kernel; the emitter builds a different description of the same kernel in control flow and strings.

Where it stands after the IR work

The kernel IR went from a well-formed subsystem nobody called to the thing every residual kernel is made of. Three measures moved, and three did not, and the ones that did not are the more informative half.

The shape is right; the direction of data flow is not. L3 computes the structure, L4 can now represent it, L6 prints it — and L6 still originates it. That is the same defect found and fixed twice in narrow places this session: the scheduler computed hoist_scope and the emitters re-derived the loop nest by hand; the driver selected a target and the emitters constructed their own. Both are closed. The general case is not.

Converting strings to nodes was a prerequisite for plan-driven emission, not a substitute for it, which is why the unread-plans measure correctly refused to move all the way through this work.

PART 3

Open points

Eleven, ordered by what unblocks what. Two are closed and one is under way since this document was written. The rail colour is status: blocked waits on something above it, needs a decision is yours to call, ready can start now.

OP 0
The matrix-free apply matrix verified end to end; 1 of 4 axes drives

The matrix-free action is the framework's primary product — 219 of the 520 generated files — and every kernel is emitted several times over across four axes: mesh traversal, geometry mode, element data layout, and precision. Which combinations exist was written down nowhere; it was readable only by generating the output and looking at what came out.

plans/apply_variants.py now states the rule, verified against the real tree: 181 of 181 apply kernels predicted exactly across all eleven materials. The rule has genuine content — AoS only ever appears with isoparametric geometry, and never for Taylor–Hood formulations, which is why poro-hyperelasticity and Stokes have no AoS variants at all; packed traversal applies to the Jacobian action only, never the residual; and packed isoparametric variants are skipped for TRI3 and TET4, whose isoparametric geometry is affine.

The precision axis drives. It was a literal tuple repeated seventeen times in one emitter; all seventeen now read the plan, and a test proves the difference between consulted and ignored by changing the plan and requiring the kernels to follow — drop a precision and its kernels vanish, add a third and a third full set appears. That is the precondition for the per-thread, per-warp and CUDA/HIP apply variants goal 8 asks for: adding a row is now a plan change.

The other three axes are still decided by the emitters. Precision was the one already expressed as a clean iteration; traversal, geometry and layout are branches woven through emission, and moving them is the harder half.

OP 1
Move the emitters' decisions into L3 under way — dependency analysis done

The root open point. residual_codegen.py (10,074 lines) and energy_codegen.py (8,483) decide loop structure, scope placement, stream layout, gather and scatter shape and geometry policy while building strings. The plan types for all of it already exist and are unread.

Done: the analysis family. plans/streams.py owns which field stream groups a kernel needs — the emitter keeps only how each is spelled in C. plans/dependencies.py owns dependency pruning: which roles are touched, which parameters survive, which coefficient entries are structurally zero. plans/boundary_usage.py owns whether a boundary form's coefficients reach for coordinates or current values, a question the emitter had been asking four times in two different shapes.

Done: the layout family. plans/layout.py takes 17 more functions — which shape function maps to which stream, where a field's components sit in a packed lane buffer, how tensor-product elements reorder into Cartesian order, and the mixed-order variants for Taylor–Hood. These decide the memory access pattern of every generated loop, and so whether the loads are unit stride.

Measured effect: the largest emitter contains zero free-symbol analysis, down from six references, and its text-free helper count has fallen from 32 to 18. residual_codegen.py is 9,875 lines, from 10,074. The boundary emitter is down from eight symbol scans to two, both argument validation rather than planning.

Done: kernel file naming. Which files a kernel produces and what they are called — LocalKernelPlan.name/.header and MeshKernelPlan.name/.source were already the definition, and the emitters rebuilt both from format strings. The idempotence rule the emitter carried privately (a prefix already naming its element does not get a second one) moved into the plan factory with it. This is the first move that changes the plan-consumption count: 13 unread, now 11.

Done: the kernel boundary. Which streams cross a kernel's boundary, and in what order, was written out independently at every signature and every call — eighteen chains of if dependencies.current / previous / direction at the mesh boundary alone, free to disagree with each other. plans/streams.py::mesh_kernel_stream_plans states it once and seventeen of the eighteen read it; the emitter keeps the spelling, which is that a stride is a ptrdiff_t and an output is not const. The two dependency views a boundary can take moved with it into plans/dependencies.py: an assembled matrix has no direction to apply to, an action always has one, and three emitters had been rebuilding the whole twelve-field record by hand to say the first. residual_codegen.py no longer names ResidualCodegenDependencies at all — it consumes views rather than constructing them.

The one site left out is _simplex_metric_scalar_affine_aos_wrapper_lines, deliberately. Its stream set is genuinely narrower — one field, current exclusive-or direction, no previous — because the specialization is only selected for forms shaped that way, and it spells its scalar type from the precision axis. Teaching the plan that shape would serve exactly one consumer, and the duplication argument that justified the other seventeen does not apply to a single site.

Remaining: the rest of the structural family — loop nest and bounds, scope hoisting, gather and scatter shape, and geometry mode. These are the genuinely hard ones: unlike everything moved so far, they are not code that lifts out whole but structure that exists only as the shape of the emitter's control flow. The mesh phases, for instance, are spread across six large emission functions, each interleaving gather and scatter with buffer declarations that depend on the dependency set. They are what OP 2 and OP 4 wait on.

The measure had to be fixed before it could report any of this. test_emission_is_a_printer counts branches in the emitters whose test reads planning-layer input, and it matched 'dependencies' quoted inside the AST dump — so state_dependencies, quadrature_rule, matrix_format_plan, stream_layout and every other qualified name read as not-a-decision. 130 branches, 30% of the real population, were invisible; converting eight of them moved the number by exactly zero, which is how it was found. The measure now walks identifiers, the budget was re-baselined 298 → 412 once for that reason alone, and the boundary work then took it to 404. This is the second time on this branch that the metric rather than the code was the thing to fix — the first was counting emitter lines, which rose through the IR migration and scored progress as regression. A measure that cannot move is worse than none, because it certifies.

OP 2
Delete _target() done — the binding replaced it

The defect was sharper than recorded here. The driver already mapped KernelTarget.CUDA onto a backend built with CUDATarget, and KernelTarget.AVX512 onto one built with AVX512Target. That target reached a language check and the energy emitter, and nothing else: the residual emitters constructed their own OpenMPTarget and ignored it. A decision made in the right layer, discarded by the layer that needed it — the same shape as the scheduler's hoist_scope.

targets/context.py binds the target for the duration of an emission; backends bind theirs in emit(), and the four emitter modules that built their own now read it. Bound rather than threaded, on purpose: 112 call sites in 49 functions ask for a qualifier or a pragma, and none of them chooses a target, so 49 extra parameters would record plumbing rather than a decision.

Proven by driving a probe target through the real backend: 39 of 90 lane-loop pragmas take the probe's spelling. The other 51 do not, because 66 pragmas were written as string literals that bypass the target — 35 converted, 31 under a shrink-only ratchet — 24 in the residual emitter, 11 more once energy_codegen's leaf pragmas moved onto the source_builder it already receives. No generated output changes, because the AVX512 and ARM targets spell everything exactly as OpenMP does: the wiring was dead rather than wrong. The 31 that remain are held back by three distinct reasons, recorded in the ratchet: 7 are parallel regions with a work-sharing for inside, which are structure rather than spelling and would compile into a serial loop in a bare block if an accessor returned nothing; 7 sit in scatter helpers that take no builder; 1 is OpenMP-specific thread-scratch infrastructure; the other 16 are in the residual emitter, which has no accessor for them yet.

OP 3
Make the six assembly plans drive assembly 1 of 6 done

CRSAssemblyPlan, BSRAssemblyPlan, DIAAssemblyPlan, COOAssemblyPlan, PatchAssemblyPlan and BlockDiagSymAssemblyPlan describe row pointers, column indices, block layout and accumulation policy. They were referenced in exactly three places: their definition, the facade re-export, and their own test.

CRS is converted. _scalar_crs_matrix_scatter_lines takes the plan and spells what it defines; the plan's defaults are the names the kernels have always used, so the text is unchanged, but changing the plan now changes the kernel. The reduction policy goes through a helper that raises on a policy it cannot spell rather than silently emitting a plain add. The other five have the same shape.

The two-stage approach holds: consume the plans at byte-identical output first, which proves they describe what is actually emitted, and only then change what they say — which is where OP 6 becomes the blocker.

OP 4
Route the residual path through KernelAST under way — two kernels in

ir/kernel_ast.py is a complete, well-formed kernel IR: typed loops with vectorization and tabulation strategies, buffers, gather and scatter nodes, geometry nodes, plus KernelASTPass and KernelASTPassPipeline. The residual path now builds nodes for two kernel bodies and for every statement helper feeding them, so the sympy-to-C bridge and the chain rule produce IR rather than text; the energy path still uses four fragments, and the pass pipeline is still referenced only from tests.

Every optimization the PRD asks for — vectorization, unrolling, blocking, scratchpad packing, per-warp variants — is a pass over this IR. There is nowhere else for them to live, and today nothing to attach them to.

OP 5
Enforce the one-dispatch-axis rule needs a decision

Two of the three architectural rules are enforced by tests. The third is not: nothing currently fails when a backend branches on unit.kind or a printer on if "crs" in formats. Both still happen.

A static check is feasible — flag string comparisons against a known vocabulary of upper-layer concepts inside lower-layer modules — but it will be noisy until OP 1 and OP 3 remove the real cases. The decision is whether to write it now as a failing ratchet with an allowlist, exactly as the layering test was written before the code moved, or wait.

OP 6
The performance gate closed

tools/apply_bench.py generates a material, compiles the real operator with the real flags, and drives all nine matrix-free apply kernels laplace/HEX8 emits over a Cartesian hex grid — six standard-traversal variants and three packed, the latter needing a real mesh partition with contiguous owned node ranges, shared nodes at the end of each range, and a ghost-reduction structure for the two-pass kernel.

It catches three independent failure modes: variants disagreeing with each other, the answer moving uniformly (cross-variant parity is blind to that — proved by a negative test that slipped through before the digest was added), and throughput regressing. Packed affine measures 30.4 MDOF/s against 23.2 for the standard traversal, the first time this branch has confirmed the PRD's claim for it.

Tolerances are four classes, not one number, and getting that wrong produced two false failures before it was right: geom_t is float, so kernels deriving the element metric differently agree only to geometry precision, and packed traversal reorders the summation so it agrees to a few ulp rather than bit-for-bit.

OP 10
Kernels validate the matrix graph per element unwanted overhead

Raised by Patrick, not found by this analysis. The generated Hessian assembly checks that the sparsity pattern contains every entry it needs while assembling. Each element's _scatter_bsr walks N_SHAPE × N_SHAPE candidate entries and tests each one with a three-condition branch, keeps a valid_block_graph flag, and calls std::fprintf(stderr, …) from inside an OpenMP parallel region on failure. The caller folds the status per element into invalid_matrix_graph and reduces it across threads with reduction(|:invalid_matrix_graph).

Graph validity is a property of the mesh and the sparsity pattern together — invariant across every element and across the whole assembly call. Establishing it once costs O(nnz); re-testing it inside the loop costs O(elements × N_SHAPE²), which is 100 branches per element for TET10 and far more for the higher-order hexes. Kernels must be correct, but preconditions belong to the caller: a kernel should be lean, and the priority inside an element loop is throughput.

Two facts shape the work. The check is fused into the sparsity search rather than sitting beside it — ks[j] is the search result and the branch validates it in the same pass — so removal keeps the search and drops the test, the flag and the I/O, rather than deleting a loop. And the CRS form carries the same pattern but is not currently emitted for any shipped material, so the real removal is smaller than the emitter source suggests.

Note that the reduction clause plumbed through parallel_for_pragma in OP 2 exists to reproduce this check byte-for-byte. That was the right transitional move under a byte-identity gate, and it is not settled design: if the check is hoisted, the clause and its target API go with it.

OP 11
Generated kernels carry dead temporaries and aliases deferred — residuals must be reproduced first

Raised by Patrick, and still true of current generation rather than only the older generator. A scan of the 508 generated sources finds 358 declarations that are a pure alias of another name — const scalar_t material1 = weak_mat_tmp4;, with material1 and material3 aliasing the same temporary — and 343 declarations never referenced again.

Both have identifiable causes. _physical_gradient_nodes emits all dim physical components unconditionally, so a form using a subset gets dead ones: u0_grad_1 and u0_grad_2 are unread while u0_grad_0 is live. The dependency set already records which components are needed as dependencies.gradient_coefficients[row][d], so the emitter has the information and ignores it. The aliases are a material-slot to CSE-temporary mapping that could be substituted at the use sites instead of named.

This work is deferred until the residuals have been reproduced, and the reason is the verification posture rather than the difficulty. Every change on this branch has been proven by 520 generated files coming back byte-identical. Removing dead declarations changes that text by design, so byte-identity stops being the proof and becomes the thing that must break. The gate becomes the apply bench — parity across all nine variants and the answer digest, both of which must be unchanged, since deleting code nothing reads cannot move a number — and the snapshot is then re-recorded as a deliberate act. Doing that while results are being reproduced would make an output change and a reproduction run indistinguishable.
